## 一、P0 · E5 数据盘点错误（附铁证）

### 问题 1：工作⓪ 的"三维数据全部在库"用的是错误的关联字段与行数

**级别**：P0

**文档现状**（四处同源，均待改）：
- [八项工作设计稿.html L221](../../设计图总览/Prism-Agent-八项工作设计稿.html)：工作⓪ 步骤 1"银河 E5（series_id=7650）三维数据全部在库——销量 sales_series_weighted(118行,2025-2026) + sales_trim(255行)；配置 config_snapshots(E5 在库 version=3, fetched_at=2026-09-30 09:06)；口碑 owner_reviews(全库 123,214 行)"
- 同文件 L691：重复同一组数字
- [任务清单.md L37](../设计图总览/Prism-Agent-任务清单.md)：D0.5 同上
- [项目提纲.md L486](../设计图总览/Prism-Agent-项目提纲.md)：下一步 1 同上（销量 255 行 / version=3）

**实测证据**（autohome.db，2026-10-02）：

| 文档写的 | 库中实测真相 |
|---|---|
| `series_id=7650` 三维通用 | **只有 `config_snapshots` 有 `series_id` 列**。`owner_reviews` **根本没有 series_id 列**（只有 `model_id` / `spec_id`），必须用 `model_id=7650` → **1274 条口碑** |
| 销量 `sales_series_weighted` **118 行** | **118 = 库里所有"含 E5"车系之和**：五菱E5 19 + 凯翼E5 7 + 别克E5 20 + 天际ME5 6 + 威马E5 4 + 思皓E50A 16 + 蓝电E5 20 + **银河E5 20** + 领汇e5 6 = **118**。**银河E5 自己只有 20 行** |
| 销量 `sales_trim` **255 行** | 银河E5 实测 **286 行**（24款/26款 共 10 个版型 × 约 28 行），255 复现不出来 |
| 配置 `version=3`，fetched_at=2026-09-30 09:06 | 实测 **version=5**，fetched_at=**2026-10-01 02:47:27**（数据在拍盘后被刷新过） |
| 销量区间"2025-2026" | `sales_series_weighted` 的 month 是 `'1'…'9'`（纯数字），`sales_trim` 的 month 是 `'1月中'/'1月末'`（**半月片**）——**两表粒度与格式都不一样**，D4"月度粒度"需先聚合 |

**为什么是 P0（而不是普通笔误）**：
118 这个数恰好暴露了原始盘点的取数方式是"用 `LIKE '%E5%'` 把所有重名车系加总"（别克E5 / 蓝电E5 / 上汽奥迪 E5 Sportback / 五菱E5 / 凯翼E5 / 威马E5…）。这正是棱镜方法论里最该防的"拿相邻车系数据补缺"，也正是任务清单 trap task 要瞄准的错。**D1.1 若照此执行，第一份交付物会自带这个错。**

**建议动作**：按下方"实测对照表"重写工作⓪ 步骤 1 / 八项稿 L691 / 任务清单 D0.5 / 提纲 L486，并补三条防错纪律：
1. 口碑一律用 `model_id`，销量一律用 `series` 精确匹配（`= '银河E5'`，禁止 `LIKE '%E5%'`）；
2. 所有数字带 `as_of` 时点（本轮已证明 config 数据隔天就刷新，静态数字必过期）；
3. 两表 month 粒度不同，取数前先统一口径。

## 二、P1 · 口碑维度名错

### 问题 2：D1.2 的维度集与真实字段不符

**级别**：P1

**文档现状**：[八项稿 L223](../设计图总览/Prism-Agent-八项工作设计稿.html)"从 review_tags 取 E5 已打标口碑，按维度聚合（**舒适性/车机/NVH** 等）"。

**实测证据**：`review_tags` **没有 `dimension` 字段**，只有 `tag_category` / `tag_name` / `sentiment`。E5（model_id=7650）的 `tag_category` 实为 **9 类**：

| 维度 | 条数 |
|---|---|
| 智能化 | 511 |
| 舒适 | 487 |
| 空间 | 455 |
| 续航 | 404 |
| 性价比 | 342 |
| **其他** | **276** |
| 外观 | 273 |
| 驾驶感受 | 268 |
| 内饰 | 219 |

合计 3235 条标签。**"车机""NVH"不是类目**（分别落在"智能化"和"舒适"里）；且**存在 276 条的"其他"兜底桶**——PM 口径聚合必须显式处理它，否则"结构性短板"的分母是错的。

**建议动作**：把 D1.2 的维度清单改为实测 9 类，并明确"其他"桶的处理规则（剔除 or 单列）。
