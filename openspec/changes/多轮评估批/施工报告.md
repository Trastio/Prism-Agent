1. **`--approve` 在 pi 层**（pi_gateway.mjs:328 spawn 参数）——但**不能拦插件级 permission 弹窗**：冒烟实证 permission-system 的 "Permission Required" 对话框仍走 extension_ui_request 流（multi-05 单题 8 个、multi-11 单题 11 个、skill-03 单题 15 个）。T0 原假设"关 AUTO_APPROVE 后 permission 弹窗可能挂死"坐实为**必然发生**，故网关侧 30s 兜底必加（已加）。

3. PRISM_LANGFUSE_BINDING 缺省开（runner.mjs:673 `!=='0'`）✓。
4. prism.py eval 网关注入走 `_eval_services()` env dict（:128），追加 env 直接改 dict ✓。

**T0 之外的关键发现（改变 T3 设计的事实）**：api 层 `resolve_user_id`（main.py:531）把 /chat 的 body user_id **覆盖为登录 token 用户名 'eval'** → 网关 RPC 池全部键控在 'eval' 下（10-20 串味修复时已记录此行为，本 change 最初设计遗漏）。后果：runner 的 ui-response/abort 回填若带题级 `eval_multi-XX` 会 404 no active session → pi 等回填挂死。修法：runner 记录 `AUTH_USER`（登录身份），ui-response 与 abort 统一用它。
