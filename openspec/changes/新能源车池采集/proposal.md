# proposal · 新能源车池采集

日期：2026-10-16 · 规格：**轻量十步**（Step7 隔离审查不省；施工 fork 型子代理）
上游：`设计图总览/Prism-Agent-新能源车池扩容方案-v1.md`（本 change 只做其 §1-§5 采集侧）

## WHY

配置/口碑看板可分析车系仅 22/289（新能源 25 万以下在售盘子）。缺口根因是采集池历史遗留未滚动。本 change 把车池数据补齐到"底座全量+深采 77"，让看板和 agent 的可分析对象扩到 ≤99 个车系。**写生产库（prism-dashboards/data/autohome.db）**，故立 change 而非裸跑。

## 关键决策（已拍板继承 + 本 change 细化）

1. 只做新能源/HEV 排除/25 万以下/SUV+三厢+MPV（上游方案 §2）；
2. 深采 300 条/车系 cap 可得量；长尾 190 只进底座；
3. **深采分两晚**（explore §2 请求量修正 ~2.4 万）；
4. delete+insert 禁入存量 22 分析池车系（启动时交集校验 fail-closed）；
5. 补账走 tag-only，不重采；
6. 看板分级徽标、月度滚动扫描 = 后续 change，不在本票。

## 验收（T6 完成定义）

- [ ] nev_pool.json 双断言通过 + 深采批 77 个绑定率 100%（或例外在案）
- [ ] 底座批后：289 车系壳+配置齐（缺项=例外清单在案）
- [ ] 深采批后：77 车系口碑 = min(300, 可得) 且缺量声明；打标 ≥70% 者进分析池
- [ ] 抽查 5 个新车系：三看板数字与库可复算一致；as_of 逐系正确
- [ ] 存量 22 车系行数前后不变（备份基线对账）
- [ ] 补账 5 车系打标 ≥70%
- [ ] 全量 pytest + smoke 绿；E2E 一个新深采车系 resolve→query→结论→submit_conclusion 过闸
