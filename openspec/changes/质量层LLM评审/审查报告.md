**P1-1 sidecar 跨槽指纹失效缺口——换 prompt 后其他裁判槽的旧分可被复用（正是"新 rubric 读旧缓存"的路径）**

`eval/quality_judge.mjs` judgeBatch（完整边界摘录）：

```js
async function judgeBatch(reportPath, report, taskIds, judge) {
  const sidecar = loadSidecar(reportPath) || { report: ..., prompt_version: ..., prompt_fingerprint: ..., rounds: [], by_judge: {} };
  const chainKey = judge.map((c) => `${c.name}/${c.model}`).join(' > ');
  const slot = sidecar.by_judge[chainKey] ??= { items: {}, usage: { prompt_tokens: 0, completion_tokens: 0, requests: 0 } };
  const fresh = sidecar.prompt_fingerprint !== PROMPT_FINGERPRINT;
  if (fresh) slot.items = {}; // 指纹变了旧条目全失效（不同 prompt 的分不许混用）
  ...
  sidecar.prompt_version = PROMPT_VERSION;
  sidecar.prompt_fingerprint = PROMPT_FINGERPRINT;   // ← 全局字段在本次运行末尾即被覆盖
  sidecar.judge_provider = judge[0]?.name ?? '';
  ...
}
```

问题：指纹失效是**全局字段比对+只清当前槽**。指纹变更被第一次运行观察到后，`sidecar.prompt_fingerprint` 立即更新为新值；本次运行没碰的其他裁判槽（by_judge 其他 key）的旧 prompt 条目原样保留，后续运行打开该槽时 `fresh=false` → 直接复用旧 prompt 的分。违反自己声明的不变量"不同 prompt 的分不许混用"。复现序列：①v3 下跑 `--judge glm`（GLM 槽入 8 条）；②prompt 升 v4 后只跑 `--judge kimi`（Kimi 槽重判，GLM 槽未触碰，全局指纹已变 v4）；③再跑 `--judge glm` → fresh=false，GLM 槽把 v3 prompt 的分当 v4 结果复用。修法：槽内自存指纹（slot.prompt_fingerprint）或指纹变更时清空整个 by_judge。当前案卷未受污染（两槽均为纯 v3 分，GLM 槽 8/8 与 rounds[3] 吻合，已验证），属必踩的演进雷而非已爆雷。

export async function callJudgeOnce(judge, userText) {
  let total = 0; let lastErr = '';
  for (const c of judge) {
    for (let attempt = 1; attempt <= ATTEMPTS && total < MAX_TOTAL_ATTEMPTS; attempt++, total++) {
      const r = await rawCall(c, userText);
      if (r.err) { lastErr = `${c.name}/${c.model} ${r.err}`; }
      else return { content: r.content, usage: r.usage, used: `${c.name}/${c.model}` };
      await new Promise((res) => setTimeout(res, 1000 * attempt));
    }
  }
  console.error(`[judge] 候选链耗尽（${lastErr}）`);
  return null;
}

### P2（健壮性）：**10 项**

**P2-1 parseJudgeJson 的 Number 强转洞**（L228-237）：`Number(null)=0`、`Number(true)=1`、`Number('')=0`——`"d3": null/true/""` 被静默收作合法 0/1 分，`confidence: true` 收作 1 过闸（均已实测复现）。削弱"schema 非法（自相矛盾形态）→弃"的机械闸。修法：先验 `typeof obj[k] === 'number' || /^\d+$/`。
**P2-2 模板替换 $ 模式注入**（judgeTask L247-250）：`String.replace` 的替换串会解释 `$&`/`` $` ``/`$'`——question/reply_full 含这些序列时 userText 被改写（实测 `'x{question}y'.replace('{question}','a$&b')` → `xa{question}by`）。修法：replacement 传函数 `() => value`。
