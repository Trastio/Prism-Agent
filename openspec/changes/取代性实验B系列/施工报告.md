### W1 关键设计

- **布防守卫（关键）**：`.pi/extensions/*/index.ts` 会被 pi 自动发现（`pi-windows-x64/docs/extensions.md` "Extension Locations"）——不设防会污染 A 系列/生产新 spawn 的工具面。工厂函数 `PRISM_CHALLENGER=1` 才注册工具，否则 no-op（单测断言：无 env 注册 0 工具，env=1 恰注册 run_sql/read_file）。
- **run_sql 只读三重门**：①校验层 `validateSql` 仅放行单条 SELECT/WITH（剥注释判首词；多语句/PRAGMA/ATTACH/写词一律拒）②打开层 `file:…?mode=ro` URI + `readOnly:true` 选项 ③会话层 `PRAGMA query_only=ON`。绕过①也写不进（单测直证：ro 库上 INSERT 抛 readonly）。
- sqlite 通道：`node:sqlite` 内置模块（Node≥22.5/Bun≥1.2；guardrails 禁 better-sqlite3 是 NAPI panic，node:sqlite 无此问题）；导入失败兜底 spawn 系统 node 同款只读查询（SQL 走 env 传递，无 argv 注入面）。
- 20KB 自截断：JSON 序列化超 20*1024 字符截断并附 `{"_truncated":true,"original_chars":N}` 标记（单测覆盖两侧边界）。
- read_file 白名单：仅 `SKILL-A.md / SKILL-B.md / schema.sql` 三个相对名；`@` 前缀与首尾空白归一放行，路径分量/绝对路径/大小写变体一律拒。
- 库路径：缺省 `eval/snapshots/snap-20261012-1222/autohome.db`（判分同快照），`PRISM_CHALLENGER_DB` 可覆盖；`db="sentiment"` 恒切同目录 `vehicle_sentiment.db`（两库同快照成对）。

### W4 runner `--challenger` 模式

判分走 challenger_check（no-verdict 纯文本）：truth 六分制断言（复用 checkTruth，含 expect_gap 缺口正确拒绝）+ trap 纯正则路径（复用 trapBlocked，verdictFail=false/verifiedPass=false）+ 越界（复用 checkOverreach 单源）+ rubric（复用 checkRubric）+ expect_gap；`result.verdict` 恒 `'none'`；首轮消息前缀带 SKILL 路径指示（臂由 `PRISM_CHALLENGER_ARM=a|b` 选，前缀指到 SKILL-A/B.md）；报告落 `eval/challenger-report.json`（归档名 `challenger-<run_id>.json`，不覆写主报告），`challenger: true` metadata + `audit` 编造率抽检清单（buildAuditList：数字锚题的金标锚 vs 回复实数，供 SQL 复算）；覆盖率闸不适用（挑战者无轨迹）；langfuse 写入与 dataset 绑定跳过（防污染 A0 基线观测）；回归比较跳过（臂间判分通道不同，A0 须 no-verdict 重放对齐——proposal 决策 3）。

challenger_check 另有独立 CLI：`node eval/challenger_check.mjs <challenger报告.json>`（离线重判 + 抽检清单，main-guard 零副作用）。
