# proposal · 质量判分 v7：多轮逐轮口径 + 判分链资格硬锁 + 后置只读

> 立项依据：EVAL_STATUS 2026-10-29 凌晨终局节——v7 修复范围升格三合一。
> 两起夜跑事故（find-gap 链降级污染 sidecar / v1.4 判分同根作废）与 multi 族 12 行 D1=0 冤案的共同根治。
> 性质：评估侧 change，不动 agent 提示词、不动 runner 主链、不动主分判分器。

## 一、要解决的问题（三合一对应关系）

### v7① 多轮逐轮口径（修冤案）
- **实锤**：runner.mjs:637 `question: (turns[0].message || '').slice(0, 40)` —— 报告行的 `question` 是**首轮消息截断 40 字**；
  而 `reply_full` 是**末轮回复**。quality_judge 的 USER_TEMPLATE 拿这个错位题面判分 → multi 族 12 行 D1=0 全冤案
  （multi-02 t3 问"车主最满意"→末轮答"好开好停"正确；multi-12 t2 问海豚销量→答 16,879 精确）。
- **数据基础（已核）**：两份目标报告（v13-final-merged.rescored.json 188 行 / eval-2026-10-28T15-39-08-403Z-r3.rescored.json 189 行）
  的多轮行均带 `turnMessages`（runner.mjs:649，逐轮**实际发送**消息，80 字截断）。
  报告只存末轮回复，中间轮回复不可得（runner 未落盘）——如实声明，不脑补。

### v7② 判分链资格硬锁（修夜跑事故根因）
- **事故链**：`selectJudge` 探测期按可用性排序 + `callJudgeOnce` 候选链降级（5.3→4.7→4-flash→Kimi）。
  凌晨限流时：①探测期 429 → 链头落到无资格模型；②逐题 fail-soft 降级 → 189 行全落 glm-4-flash（校准已否的裁判，
  completion 2.3 万敷衍量级）→ 废数据写回 sidecar 污染正版。find-gap 后置模式与全量判共用主链还会**重判+写回**。
- **定性**：设计缺陷（降级无资格约束）非运维失误。**宁缺毋错没有硬约束 = 比没有数据更危险（废数据看着像真的）**。

### v7③ 两报告统一重判（事故损失转计划）
- v1.3 六维明细被 checkout 误删（sidecar 只剩校准期 8 items，已核）；v1.4 判分作废已删。
- 反正 v7① 改模板后指纹变更全量失效（P1-1 语义）——v1.3+v1.4 两报告**必须**统一重判，一次重产明细真值。

## 二、设计

### D1. 模板分型（PROMPT_VERSION v6→v7）
- **单轮行**：userText 与 v6 **逐字节一致**（模板不动）——校准集 8 题全单轮，ρ 连续性可期。
- **多轮行**（`turnMessages` 为数组且 length≥2）：三段式（拍板"首轮+末轮+末轮回复"的超集实现——中间轮问题一并给全，
  "逐轮问答对"里的问全给、答只有末轮如实声明）：

```
【用户问题】（维度：{dimension}；多轮对话，共 {n} 轮）
本题是同一会话里的连续对话。各轮用户消息依序如下：
第1轮：{t1}
第2轮：{t2}
第 {n} 轮（最后一轮）：{tn}
下面的助手回复只需回答「最后一轮」的问题；前几轮问题仅供上下文。

【助手回复全文】（针对最后一轮问题的回复）
{reply}
```

- turnMessages 缺失或 <2 轮 → 回退单轮模板（旧报告兼容）。
- v6 全文入 PROMPT_ARCHIVE.v6（指纹 8b7c7620，与 sidecar 现存值一致）。
- JUDGE_SYSTEM_PROMPT 不动。

### D2. 资格硬锁
- `QUALIFIED = ['GLM/glm-5.3-flash']`（v6 校准 ρ=0.73 过阈坐实；Kimi 余额停机未在 v6+ 校准，不入链）。
- `selectJudge`：全量判/后置模式只在资格链内探测组链；资格链全败 → 硬错退出（信息含"宁缺毋错"），**不降级**。
- `callJudgeOnce`（资格链语义下）：HTTP 429/5xx = 限流类 → **指数退避等待重试**（15s/30s/60s/120s/240s，封顶 300s 循环），
  单题墙钟预算 10 分钟（env `PRISM_QJ_ROW_BUDGET_MS` 可调）；耗尽 → 该题 null（fail-soft 保留），null_reason 如实声明。
  其他传输错维持 3 次快重试。**链外模型永远不会被调用**。
- `--judge` 参数：仅接受资格链内提供方；`--judge kimi` → 拒绝并提示"需先 --calibrate 过阈才有资格"。
- `--calibrate` **例外允许任意候选**：资格由校准产生，试新裁判是校准的本职（否则永远无法扩链）。

### D3. 后置只读（--post / --find-gap）
- 不再走判分主链：直接读 sidecar 资格槽 items；缺判行**报数不补判**（提示先跑全量判）。
- **零 LLM 调用、不写 sidecar**（教训②"后置读模式只读不写"根治）。
- find-gap 仍为纯本地比对（items 已在 sidecar）。--post 只写 langfuse（幂等 id=runId|taskId|repeat|quality-score，
  重判后重发=同 id 覆盖为 v7 口径分——**有意为之**：A/B 两臂必须同一方法论）。

### D4. 重判运维序列（v7③，非代码）
1. **校准复验**（放行闸）：v7 prompt 下 `--calibrate --judge glm`，ρ≥0.7 exit 0 才继续（资格在 v7 下重新坐实）；
2. v1.3 全量 188 行 → 3. v1.4 全量 189 行 → 4. 双报告 `--post` + `--find-gap`（只读）。
- 白天窗口跑（夜间限流窗口禁判分）；驱动脚本带探测失败重试环（15min 周期）——重试的对象是**启动探测**，
  判分中途的 429 由 D2 预算内等待消化，不再需要杀进程。

## 三、验收
1. 单测全绿（新增：模板分型/归档指纹/硬锁过滤/429 退避/只读后置）；
2. 校准复验 v7·glm-5.3-flash ρ≥0.7 PASS（exit 0）；
3. 双报告重判完成：单轮行分布与 v6 相容（抽样对照）、multi 族 D1 冤案消除（multi-02/12 锚行 D1≥1）；
4. --post 后 langfuse quality-score 两 run_id 各自计数 = 各自有效行数；--find-gap 零 LLM（本地秒出）；
5. EVAL_STATUS 发版门槛正式结论（配对 Wilcoxon on 质量分 + D5/D4 维度 + 单轮子集）随本 change 归档。

## 四、不做
- 不改 runner 落盘结构（turnMessages 80 字截断如实沿用；全量落盘留愿望单）；
- 不改主分判分器/trap/判分链（rescore 侧另有体系）；
- 不动 agent 提示词（受众分层 A/B 的两臂语料不许再变——重判是后置重放，判的是既有回复）。
