## 2.1.1 AGENTS.md + SYSTEM.md

### 设计（两层提示词，教材 §3.2.12）

**AGENTS.md（全局层，永不动）**——棱镜 SOP：
- `<prism_dimensions>`：配置=产品力 / 口碑=需求验证 / 销量=市场结果 / 舆情外挂第四组
- `<red_lines>`：数据真实性硬底线 / 不写裸 SQL / 权限分层 / 舆情合规 / 护栏在执行层
- `<discipline>`：报告纪律六条（可复算SQL / 逐维as_of / 结论不越界 / 数据缺口假设 / 分层规则 / 对象身份前置核验）
- `<gap_assumption_pattern>`：数据缺口下假设清单范式（假设+证据强度+缺什么能坐实，不硬下结论）
- `<layered_rules>`：默认顺序推进；查完一维后允许带疑问回查；禁止某维没查完就用别的维度下结论

**SYSTEM.md（会话层，锁快照）**——`before_agent_start` 动态注入：
- 当前会话的车系/对象身份映射结果 + 覆盖率
- 当前 as_of 快照
- 三维度完成度状态

### 验收
- AGENTS.md 内容固定不可被会话修改
- SYSTEM.md 每次会话按对象身份注入
- 红线规则在提示词层 + 工具层双重出现（提示词劝说 + 工具强制）

## 2.1.2 状态栏 hook

### 设计（教材 §3.2 chapter2/system-hint/agent.py:858-862 照抄）

SystemState 字段：
- 当前车型 / 对象身份映射状态
- 三维度完成度（配置/口碑/销量 各 0/1）
- 工具调用计数（≥3 同维度告警）
- 剩余 token / max_iterations 硬闸门
- as_of 当前快照

注入顺序：状态栏 → memory → mem0（总 16K）→ D3 来源标记

### 验收
- 状态栏每轮更新
- max_iterations 到硬闸门 fail
- 同维度工具调用 ≥3 次告警

## 2.1.3 D3 来源标记 + 数据缺口假设范式

### D3 来源标记
口碑/销量/配置内容全包 `<external_content source="review_tags:model_id=7650">` 标签，便于溯源。

### 数据缺口假设范式（报告③ v2 范式固化）
当覆盖率守卫报告缺数据时，agent 必须输出：
```
## 数据缺口声明
- 缺失维度：[舆情/区域销量/订单/...]
- 假设清单（画靶，标证据强度）：
  - 假设1：... | 证据强度：强/弱/不可验 | 缺什么能坐实：...
  - 假设2：...
- 不下结论
```

### 验收
- 铂智7X 场景触发数据缺口范式（区域数据不可得）
- 所有数字带 source 标签
