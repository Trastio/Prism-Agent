## 核心问题

**精简 agentDir 一刀切禁了所有插件**——为了避开 pi-memory 干扰，把 langfuse / cc-safety-net / pi-permission-system 全禁了。

这跟白名单过严是**同一类错误**：修一个问题时没考虑连带影响。

## 应该怎么修

精简 agentDir 应该**精准禁 pi-memory + mem0**（干扰源），**保留其他全部**：

```json
{
  "packages": [
    "npm:@gotgenes/pi-permission-system",
    "npm:@juicesharp/rpiv-ask-user-question",
    "npm:@langfuse/pi-observability-plugin",
    "npm:cc-safety-net@2.4.15",
    "npm:@narumitw/pi-usage",
    "npm:pi-web-access",
    "npm:pi-subagents"
  ],
  "extensions": [".pi/extensions/prism-guardrails/index.ts"],
  "compaction": { "enabled": true, "reserveTokens": 16384, "keepRecentTokens": 30000 }
}
```

+ 设 LANGFUSE_PUBLIC_KEY / LANGFUSE_SECRET_KEY 环境变量
+ 装 qmd（pi-memory）或确认不需要

## 但这里有个更深的问题

**cc-safety-net 和 pi-permission-system 在 RPC 模式下需要 UI 确认（extension_ui_request）**。

当前 pi_gateway 的 extension_ui_request 自动回填（PRISM_AUTO_APPROVE_UI=1）——等于所有确认自动通过，cc-safety-net 和 permission-system 形同虚设。

要真正生效：
- pi_gateway 需要把 extension_ui_request 转发给前端
- 前端弹确认框
- 用户选择后回填 extension_ui_response

这是**架构级改动**——RPC 模式下的 UI 交互需要双向通信（当前只有 pi→前端单向事件流，没有前端→pi 的命令通道）。
