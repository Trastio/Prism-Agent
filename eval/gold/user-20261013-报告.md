## 0. ⚠️ 与 explore.md 冲突的最高优先级新发现：销量"9月末剧变"是跨年聚合误读

explore.md §2 声称"10-11 导入 CAM 9月末批后部分车系 9月末有零售（862/1296），E5 9月末 10,377、8月末 15,210（15行）均有值，旧记忆已过时"。**逐项复算证明这是错的**：

| explore 声称 | 快照实测 | 结论 |
|---|---|---|
| 9月末零售部分覆盖 862 车系 | `SELECT COUNT(DISTINCT series) FROM sales_trim WHERE month='9月末' AND retail IS NOT NULL` = 862，**但全部落在 year=2025**；`WHERE year=2026 AND month='9月末' AND retail IS NOT NULL` = **0** | 862 是 2025年9月历史行 |
| 银河E5 9月末 10,377（10行） | E5 2025-9月末=10,377（10行，24款+26款）；E5 **2026**-9月末 = 5行 retail 全 NULL | 10377 = 去年9月 |
| E5 8月末 15,210（15行） | 2025-8末 10,774（10行）+ 2026-8末 4,436（5行）跨年求和 = 15,210 | 跨年聚合，无意义 |
| MG 4X 无 9月末行 | MG 4X 有 2026-9中/9末行（各4行）但 retail NULL | 行在、值无 |
| （未提）WAL 风险 | 复制 db+wal+shm 后读写打开（应用 WAL）再查 2026-9末 = 仍是 NULL | 非 WAL 视图问题 |

**口径定论（金标据此）**：sales_trim 的 (year, month) 是自然日历时间，全库时间轴 2025-01末 → 2026-09末；**2026-09月中/末行 retail 全库为空（价格 tp 有值，零售字段滞后——与 Phase3 旧记忆"月末批零售滞后、口径停8月末"一致，explore 的"已过时"判断反而过时）**。全库零售最新有值月 = **2026-8月末**（1,140 车系有值）。per-series 最新有值月：E5/B10/B01/A10/MG4X/海狮05 EV+DM-i/海狮06 EV+DM-i/星愿/QQ3/风云A9/A9L → 均 2026-8月末；风云T7 → 全库无零售。

因此**口径A（每车系最新有值月）在本快照下自然收敛为"几乎全部=2026-8月末"**，派单中的"E5→9月末10377"不可用（那是 2025-9月），MG4X→8月末3427 ✓、T7 全空 ✓。

## 4. query_sales 月参数与 '9月末' 形态实测记录

- **工具定义**（`.pi/extensions/prism-guardrails/index.ts` makeQueryTool）：query_sales(series_key, year?, group_by=month|spec, month? 1-12 数字)，参数透传 `${FASTAPI}/dashboard/sales?...`。
- **端点实测**（prism-api/main.py:316 `/dashboard/sales`，代码级核验）：
  - `group_by=month` 分支：`WHERE REPLACE(series,' ','') LIKE ? AND month LIKE '%月末'`，返回行 month=**数字**（`CAST(TRIM(REPLACE(month,'月末','')) AS INTEGER)`）；**month 查询参数完全不读取**。
  - `group_by=spec` 分支：同过滤，返回行 month=**原生中文串**（'9月末'），仅 year 被二次过滤；**month 参数同样不读取**。
  - 结论：**query_sales 的 month 参数是无效参数（静默忽略）**；agent 表达"某月"只能靠 group_by=spec 拿全量月末行后自筛。库内月份原生形态='9月中'/'9月末'（字符串，排序口径=月序号+末>中）。
  - **判分影响**：金标不要求传 month；要求答案锚定 2026-8月末（零售最新有值月），且不得把 2026-9月末 NULL 行当销量。工具描述债（描述称支持 month 1-12）建议 Block0/后续 change 顺手修。
- 另：sales 端点归一化 `normalize_series_for_sales`：series_key→series_summaries 精确名→`%去空格%` LIKE——所以 '零跑B10' 能查到 '零跑 B10'。

## 5. supported_by：库原生串 vs 归一名 —— 决策：一律库原生串/原生 ID

依据 = `/verify/claim`（prism-api/main.py:1107 起）各分支的真实校验逻辑：
