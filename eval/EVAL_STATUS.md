## badcase 搜集与回流机制（2026-10-31 建立，两轮评估口径）

> 口径：只做两轮——①上线前评估（题集跑分→改→复跑判显著）②上线后 badcase 回流（真实坏例→转题→复跑防复发）。
> 不做月度金标重算、不做质量层校准（见 quality_calibration.json policy=reference_only）。

### 采集信号（定义在 `eval/dynamic-tasks.ts`，全部可复算）

| 信号 | 判据 | 价值 |
|---|---|---|
| `verdict_fail` | 轨迹 `verdict=fail` | 出口闸已判失败，零成本 |
| `user_correct` | 用户末条含「不对/错了/我是说/不是这个…」 | 出口闸没拦住、但用户不认 |
| `user_rephrase` | 同 session 相邻人类提问字符二元组 Jaccard ≥ 0.6 | 上一答没解决问题（强制重问） |
| `no_answer` | conversation 末尾是 user 消息 | 问了没答（会话中断） |

- 系统注入的续跑消息（`[完成验证器] …`）**不作为题面**，回溯上一条人类消息（实测 L4 被误收，已修 + 单测锁）。
- 留档文件 `eval/badcases.json`，四件套：`question / answer / tools / verdict+verdict_reason` + `sessionId/source_line/ref_line`。
  只存问答无法定位根因——reviews-07 那次「答对了却被判 0」必须看工具轨迹与判据才看得出来。

### 回流步骤

1. `node eval/dynamic-tasks.ts --collect` → 写 `eval/badcases.json`（全量留档，人工过目）
2. 人工筛选：哪些值得进题库 → 补判据（`judge_rubric`/`truth` **绝不自动生成**）
3. `node eval/dynamic-tasks.ts` → 写 `dynamic-tasks.json`（`set=dynamic`，`--set=all` 不含，判据空则不进分母）
4. `node eval/runner.mjs --set=dynamic` → 回跑，对比原判因是否修复
