## 一、分带预筛判据（DB-only，执行前一次性算定）

对每个候选带 `(energy ∈ {BEV, PHEV}, price_min, price_max)`，带宽 2 万元，区间 8–30 万：

1. **销量榜**：`series_filter` 按 `energy + price_min/price_max` 检索，按 `latest_retail` 降序取前 5 → `R5`
2. **配置榜**：同一带内、`config_snapshots` 有快照的车系，按 `categories` JSON 的配置项数降序取前 5 → `C5`
   （配置项数 = `categories` 内叶子项计数；该字段是采集快照的原始结构，不经模型加工）
3. **分离度**：`sep = 1 - |R5 ∩ C5| / 5`
4. **入选条件**：`sep ≥ 0.6`（即两榜最多重合 2 款），且 `R5` 中至少 3 款有配置快照
5. **取数**：按 `sep` 降序取 **8 个带**；`sep` 相同按 R5 零售合计降序；再相同按 band 字典序
6. **判据无关性**：以上全部来自库内查询，**不读任何模型输出**

> 该判据直接对应失效机制：只有当"销量前列"与"配置更全"两榜分离时，"没筛池就比配置"才会漏掉金标。

## 二、题族（8 道，全纳入，不选题）

- 每带 1 题，问法统一模板：`{价格带}左右哪款{能源类型}车的配置最全`
- 金标 = 该带 `R5`（销量榜前 5）中的**前 3**
- 判分：`rubric_params.kind=ranking`，`gold_top3` + `hard_first`（表内第一）
- **只验结果**，不加过程断言
- `set: "experiment"`（不进 all / 不进 frozen）
- 配置缺口如实点名不扣分

## 三、实验设计

| 项 | 规定 |
|---|---|
| 单元 | 8 题，**全纳入**（不按任何分数筛选、不剔除天花板题） |
| 每臂 | 4 跑（A→B→B→A 四段，每段 2 跑；时间平衡） |
| 总跑次 | 8 × 8 = **64**（单窗口） |
| 题级通过 | 该臂 4 跑中 `rubric.pass` ≥ 3 |
| 主检验 | McNemar 精确单侧（`stats.mcnemar_exact`），b≥5 且 p<0.05 判显著 |
| 不显著 | 报效应量 + Clopper-Pearson 95% CI + 逐题明细，写"未达统计显著" |
| 墙钟上限 | 2 小时（64 跑 × 实测 ~90s ≈ 96 分钟） |
| 截断 | 累计 105 分钟停未开跑段；成对不足 2 跑的题整题剔除并留痕 |
| 回归闸 | **本窗口不跑**（64 跑已占满预算）→ 单独窗口跑 63 题全量；结果报告必须写明"回归闸未在本窗口完成" |

## 修订 A2.1（选带执行后、任何模型跑次之前，2026-11-02 20:05）

**触发**：按 §一 原样执行（sep≥0.6 且 R5 至少 3 款有配置快照），22 个带里只有 **4 个**合格。
n=4 时 b 最大 4 → p 最小 0.0625，**结构上不可能达到 p<0.05**，继续跑没有统计意义。

**另发现两处实现问题（已修，非口径变更）**：

1. `categories` 的叶子值是以 JSON **字符串**嵌套存储的，首版解析只处理 dict → 251 款车的"配置项数"几乎全被算成 0；修正后分布 65–309（中位 228）。
2. 市场名与配置快照名存在命名差异（"吉利星愿" vs "星愿"、"启源Q05 纯电" vs "长安启源Q05"）→ 加保守匹配（归一化后精确 / 后缀 / 前缀，且**唯一命中才算**，歧义即视为无快照，不做人工转写）。

**修订内容（两条，均为降低门槛而非挑题）**：

1. **覆盖门槛**：`R5 至少 3 款有配置快照` → **至少 2 款**。理由：n=4 无法达到显著性门槛；覆盖 2 款仍可完成横评，其余按缺口点名（与判据"缺口点名不扣分"一致）。
2. **单元数**：8 → **7**。理由：8 单元 × 8 跑按 A 轮实测（A 78s / B 116s）约 104–106 分钟，会撞 105 分钟截断线；7 单元约 90 分钟，留出余量。仍在用户批准的"6–8 道"区间内。
