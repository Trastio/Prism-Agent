# Prism-Agent 新能源车池扩容方案 v1

> 状态：**待拍板**（§10 五项，2026-10-16 讨论轮收敛）
> 来源：配置/口碑看板"车系太少"讨论 → 2026-10-16 拍板纯新能源方向
> 数据快照：2026-10-16 查询 prism-dashboards/data/autohome.db（销量=2026 年 6~8 月末批；配置 fetched 10-01~10-07；口碑 as_of 10-07）

---

## §0 TL;DR

- 现状：25 万以下在售新能源 SUV/三厢/MPV 共 **289 个车系**，口碑能支撑分析的只有 **22 个（7.6%）**；月销 >1 万的热卖车系 42 个里 20 个口碑为 0。
- 动作：三层扩容——**底座层 289 个全补壳+配置（约 309 次调用）→ 深采批 77 个口碑 300 条/车系+打标 → 长尾 190 个不采口碑只进底座**。
- 工作量：两晚跑批（底座一晚 + 深采一晚），采集器全部现成（prism-dashboards 自带），汽车之家直采不花 TikHub 钱。
- 库终态 ≈ **500MB**（现 300MB），上云无容量压力；采集面留工位机，库经一致性快照推云。
- 顺带还 5 个存量车系的打标旧账（覆盖率 34~50%）。

## §1 背景与问题

### 1.1 漏斗现状

| 层 | 数量 | 说明 |
|---|---|---|
| 在售车系宇宙（销量侧） | 1,132 | 近 6 个月有零售 |
| 25 万以下在售 SUV/三厢/MPV（全能源） | 517 | 近 3 月有零售+在产 |
| **其中新能源（本方案盘子）** | **289** | 纯电 141+插混 106+增程 42（见 §3.2 勘误） |
| 口碑达标（≥100 条且可聚合） | **22（7.6%）** | §4.2 名单 |
| 配置快照覆盖 | 部分 | 深采批 77 个中缺配置 150 项次（含壳缺失） |

### 1.2 根因

口碑池是 Atuohome 时代的历史遗留名单（元PLUS/MG4/零跑系/风云系/E5 等），从未按市场大盘滚动过。热卖新车（零跑 A10 月销 6.9 万、启源 Q05、钛7、埃安 i60、ARCFOX βS3…）全部无口碑。

### 1.3 现有分析池 22 个（口碑≥100）

比亚迪 元PLUS(2268/打标82%)、零跑 C11 增程(2000/98%)、零跑 C11 纯电(2000/98%)、风云A9L(2000/78%)、银河E5(1187/91%)、风云T11 CEM(1137/**34%**)、零跑 B10(1027/97%)、零跑 B01(954/96%)、海狮05 EV(643/**37%**)、海狮06 DM-i(560/**37%**)、海狮06 EV(560/**37%**)、元UP(483/**50%**)、小米SU7(472/76%)、银河A7 EM-i(352/91%)、银河M7(315/98%)、MG 4X(271/99%)、风云A9(265/75%)、宋Ultra EV(228/87%)、宋Ultra DM-I(228/87%)、零跑 D19 纯电(186/89%)、零跑 D19 增程(186/89%)、银河星耀7 MAX(178/97%)

（格式：条数/打标覆盖率；**加粗** = 不足 70%，进 §5.5 补账）

## §3 车池口径定义（可复算）

### 3.1 过滤条件（sales_trim）

```sql
-- 盘子 = 满足以下全部条件的 distinct series
year='2026' AND month IN ('6月末','7月末','8月末')  -- 近 3 月
AND retail > 0 AND prod_status='在产'              -- 在售且卖得动
AND body 含 'SUV'/'三厢'/'MPV'                      -- 车型④
AND energy_type 含 '纯电'/'插电'/'增程'/'燃料电池'    -- 能源①②（子串匹配）
AND 中位数(msrp) <= 250000                          -- 价格带③
```

### 3.2 ⚠️ 勘误记录（防复发）

2026-10-16 讨论轮曾报"盘子 183 个"——**错值**。当时能源过滤用全词集合（含"插电式混合动力"）对库值"插电式混合"做子串检查，全词比库值长、永不命中，**106 个插混车系被静默漏掉**（对账实证：旧结果能源构成 = 纯电 141+增程 42+插混 0）。

**制度教训**：程序化名单必须带**能源构成断言**（插混/纯电/增程三类计数均 >0 且合计=盘子数）与**盘子数环比断言**（相邻两次生成差值超阈值即报警），断言不过 fail-closed 不出名单。

### 3.3 边界与已知例外

- **跨线车系默认不进**（入门 <25 万、主力 >25 万）：理想i6(月销5.4万)、Model 3(3.7万)、小米YU7(3.5万)、问界M6 EV、大唐 EV、乐道L80、GL8 PHEV、豹5、坦克300L Hi4、智界R7 纯电。→ §10 待拍板 1。
- 极氪7X / 理想L6 中位数恰为 25.0 万，按规则**在池内**。
- **身份映射陷阱（生成时发现，施工必查）**：子串匹配会把同族车系映射到同一壳 ID——实证：秦PLUS DM-i 与秦PLUS EV 的"源站口碑量"同为 10020、星舰7 EM-i 与 EV 同为 1277、风云T9L 与"T9L C-DM"各自有 id。**名单落地必须走 API 精确 ID 绑定，子串匹配仅作初筛，歧义项人工复核，绑不上 fail-closed 进例外清单**（红线#6 名称禁人工转写）。

## §4 车池三层结构

| 层 | 数量 | 动作 | 看板形态 |
|---|---|---|---|
| **分析池** | 现有 22 + 深采后新增 ≤77 → ≤99 | 深采批达标后进入 | 配置+口碑+销量全维分析 |
| **底座层** | 289（全盘子） | 补壳(series_summaries)+配置快照，约 309 项次 | 配置对比+销量；口碑位如实标"样本不足" |
| **长尾层** | 190（月销≤3000） | 只进底座，不采口碑 | 同底座层 |
| **打标补账** | 5（存量欠账） | 元UP/海狮05 EV/海狮06 DM-i/海狮06 EV/风云T11 CEM 补打标至 ≥70% | 分析池内修复 |

### 4.1 深采批 77 个（月销 >1万 的 27 个 + 3000~1万 的 50 个）

全名单见 §附A（按近 3 月零售降序）。要点：
- 每车系目标采集 **300 条口碑**（cap 于源站可得量：A10 源站仅 187 条、深蓝L06 27 条、MONA L03 30 条、小鹏G7 21 条等按实际可得封顶，缺口如实记录）；
- 采集后打标，目标覆盖率 ≥70%。

### 4.2 长尾层 190 个

月销 ≤3000，不采口碑。名单程序化生成落 change 件（nev_pool.json），不在本文档罗列。

## §5 施工方案

### 5.1 现成资产盘点（prism-dashboards 自带，不新造轮子）

| 资产 | 用途 |
|---|---|
| `src/api/autohome_api.py` | fetch_koubei_page / get_series_summary / get_full_config / search_series / build_series_index（ID 绑定数据源） |
| `scripts/collect_config_snapshots.py` | 配置快照采集（_list_series_from_db / 增量 fresh 集合） |
| `scripts/recollect_koubei_with_full.py` | 口碑重采+打标管线（tagger 参数化） |
| `scripts/refresh_koubei.py` | 口碑刷新 |
| 现有库表 | owner_reviews(model_id=车系id) / review_tags / series_summaries / config_snapshots |

### 5.2 批次与耗时预估

| 批次 | 内容 | 调用量 | 预估 |
|---|---|---|---|
| 底座批 | 289 个壳+配置补齐（缺壳或缺配置并集 ≈309 项次） | ~310 | 一晚（限速 1-2s/请求） |
| 深采批 | 77 车系 × ~15 页口碑 + 打标 2.3 万条 | ~1,150 页 + 打标 | 一晚（打标时长以现有 tagger 实跑为准） |
| 补账批 | 5 车系打标补齐 | LLM 调用 | 随深采批同跑 |

### 5.3 身份映射流程（红线#6 落地）

1. 名单由脚本从 sales_trim 程序化生成（含 §3.2 双断言），禁人工转写车系名；
2. autohome series_id 绑定：`search_series`/`build_series_index` 精确匹配 → 同名多候选/子串歧义项进人工复核清单 → 绑定失败的 fail-closed 进例外清单（不猜测）；
3. 绑定结果落映射表（sales series 名 ↔ autohome series_id ↔ 绑定方式/时间），后续滚动扫描复用。

### 5.4 失败语义（数据真实性红线#1）

- 口碑采不满 300：落 collection_status，看板显示实际条数，不伪造；
- 打标覆盖 <70%：该车系保持"配置可见"层级，不进分析池，缺口如实声明；
- 源站无此车系/下架：记入例外清单，名单版本留痕。

### 5.5 打标补账（5 个存量车系）

随深采批同跑 backfill，达标（≥70%）后维持分析池资格；风云T11 CEM 34% 优先。

## §6 看板与产品闸门

### 6.1 分级规则

| 层级 | 门槛 | 看板行为 |
|---|---|---|
| **分析可用** | 本地口碑 ≥100 且打标覆盖 ≥70% 且配置√ | 全维分析、结论可出 |
| **配置可见** | 配置√ 但口碑 <100 或打标 <70% | 配置对比+销量可用；口碑区显示"样本不足(n 条)" |
| **仅销量** | 无壳无配置 | 只在销量/搜索出现 |

### 6.2 展示纪律

- 每车系每维度带 as_of（新采口碑 as_of=采集日；与存量老数据不同源时逐系声明，不混写）；
- 分级徽标（分析可用/配置可见/仅销量）在口碑、配置看板及侧栏搜索结果中可见；
- 搜索宇宙随壳表自动扩大（resolve_series 读 series_summaries + sales_trim），无需改前端逻辑。

## §7 上云影响评估

| 项 | 现值 | 终值 | 结论 |
|---|---|---|---|
| 库体积 | 300MB | ≈500MB（深采 +178MB、底座 +25MB） | ECS 4c16g 下 page cache 占内存 ~3%，只读聚合查询毫秒级，**无压力** |
| agent 取数 | 按车系聚合 | 不变（单次返回量与车系总数无关） | 无影响 |

**真正要设计的三件事（非容量问题）**：
1. **采集面留工位机**——汽车之家反爬对云 IP（数据中心段）不友好，跑批不上云（与"舆情采集面不上云"同一拍板逻辑）；
2. **库同步管道**——工位机用 SQLite backup API（或 VACUUM INTO）出一致性快照 → OSS → 云端拉取，500MB 日更一次分钟级；禁直接拷贝热文件；
3. **单写者纪律**——工位机单写、云端只读；上云清单追加此条。

## §8 月度滚动缺口扫描

- 触发：每月 CAM 月末批导入（import_sales_excel.py + market_source.json 更新）之后；
- 动作：重算 §3.1 盘子 → 与已绑定居名单 diff → 新上车系（如本月 ARCFOX βS3）自动进候选队列 + 盘子数环比断言；
- 产出：候选名单（标建议层级）→ 人工确认 → 进下一次采集批；
- 交付：扫描脚本 + 与 CAM SOP 文档并一行衔接说明。

## §9 实施顺序与验收

**实施顺序**（建议按严格十步流程立项，跨采集/身份映射/壳生成/看板/机制多层）：

1. 名单生成器 + 断言 + 映射表（§3/§5.3）
2. 底座批：壳+配置（一晚）
3. 深采批+打标+补账（一晚）
4. 看板分级徽标+样本不足展示（§6）
5. 月度滚动扫描（§8）
6. Step7 隔离审查 + Step8-10 归档

**验收清单**：

- [ ] 名单可复算：nev_pool.json 由脚本生成，带能源构成断言 + 盘子环比断言，生成参数入库
- [ ] ID 绑定率：深采批 77 个 100% 精确绑定或有记录在案的例外；无静默子串放行
- [ ] 深采批：每车系口碑 = min(300, 可得量) 且缺量已声明；打标 ≥70% 或未进分析池
- [ ] 抽查 5 个新车系：看板数字与库/源站一致（可复算）
- [ ] 分级徽标 + "样本不足"展示在三个看板生效
- [ ] as_of 逐系声明正确
- [ ] 全量 pytest/smoke 绿；E2E：任选一个新深采车系跑通 resolve → query_* → 结论 → submit_conclusion 过闸
- [ ] 补账 5 车系覆盖率 ≥70%
