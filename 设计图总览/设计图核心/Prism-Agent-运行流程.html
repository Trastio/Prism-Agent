▼ 模式 B 进入主循环

agent_loop（pi SDK 进程内 · DeepSeek-v4-flash）

本地 ID → DeepSeek user_id 贯穿（KVCache/调度/内容安全隔离）。每轮：注入→思考→工具→验证→(续或收尾)。max_iterations 硬闸门。
1

before_agent_start · 注入棱镜 SOP

动态注入 system prompt（非静态 AGENTS.md）：①全局层=棱镜三层推进纪律(配置→口碑→销量不跳步)+红线+结论定义；②会话层=锁当前车型/过滤态/已查维度快照。BI 嵌入会话注入受限子集。分层规则：默认按顺序推进；查完一维后允许带疑问回查另一维（双向交叉验证）；但禁止某维没查完就用别的维度下结论。

PM性·①流程骨架 | 两层提示词：全局永不动 + 会话锁快照 | 依据:chapter10/staged-system-prompt
2

状态栏装配 · 维度完成度

状态栏挂当前车型 / 配置✓口碑✓销量✓ 完成度（棱镜三维度主轴）+ 舆情✓（外挂，按需） / 工具调用计数(≥3告警) / 剩余 token 预算。agent 自见哪维没查。

PM性·②checklist | 状态栏 hook + compaction 保留完成度标记 | 舆情标记为外挂，不强制完成
3

DeepSeek 思考 · 决定本轮动作

模型基于 SOP + 状态栏 + 历史 → 输出：调用某语义工具 OR 给出最终结论。主轴遵循"配置→口碑→销量"顺序（棱镜三维度，未查配置时倾向先查配置）。舆情是外挂第四组——不在三维度主轴，但三个时机触发：①销量波动需找外部解释；②口碑与销量背离（口碑好销量差或反之）；③用户主动问舆情。

tool_call 事件触发 | 模型可提议结论，不能批准自己的结论（红线#1） | 舆情只与销量双向绑定（棱镜理论：营销变量非产品力）
4

tool_call 护栏 → 语义工具执行 → tool_result 改写

① tool_call 拦截：cc-safety-net + 自建红线拦截（fail-closed，抛错=拦）。② 工具门控：setActiveTools 按阶段/角色解锁——普通用户锁只读白名单，管理者解锁采集。③ 工具执行：query_config/reviews/sales（只读直连 SQLite）或 sentiment_*（GET only REST）。④ tool_result 改写：grounding 分维度配阈值，编造数字判 unsupported。

红线闸：工具函数体无写操作代码=结构上不可增删改；SQLite 只读连接；REST GET only。管理者写能力需弹密码（红线#3）。
PM性·③棱镜物化 | 3核心工具=棱镜三维度物化 | 依据:chapter9/safety_policy_gate.py:322

舆情工具组（外挂第四组 · 按需触发，不强制并行）：
触发时机：① 销量波动需外部解释（如某车系销量骤降，查舆情是否负面事件）；② 口碑与销量背离（口碑好销量差或反之，舆情解释背离原因）；③ 用户主动问舆情。6 个 sentiment_* 工具（对接舆情 Board 21 个 dashboard GET）：sentiment_overview / sentiment_trend / sentiment_dimension(含 dim-examples 幻觉溯源) / sentiment_posts / sentiment_competitive / sentiment_events。定位：舆情是营销/外部变量，不是产品力维度——只与销量双向绑定，不进三维度主轴。
5

循环判断 · 续 or 收尾

工具结果回填上下文 → 回 Stage 3 继续思考（若三维度未查完或结论未成型）→ 触发收尾（若结论成型）。max_iterations 硬闸门防死循环。

6

agent_settled · 完成验证器（max 1 次 continuation）

① grounding 校验：销量/配置数值维度，每个数字必有 evidence:[row_id]。② 结论完整性：每条结论带结构性判断 + 证据行 ID + as_of 时点。③ 口碑定性结论：claim 溯源 + 人工抽检（六分制对口碑失效）。④ n 与覆盖率绝不采信模型自报，服务端真值校验。不过 → max 1 次 continuation 回 Stage 3，再不过 fail。

红线#1 闸：模型可提出完成，不能批准自己的完成。独立验证器替 agent 做 PM 的"复核"。
PM性·④PM复核 | 依据:chapter8/premature-completion-dpo + chapter10/staged-system-prompt approve信号
7

agent_end · 产出交付物 + 轨迹落盘

① 交付物：结论文本（带证据行 ID + as_of）/ 可选 excel·word 文件。② 轨迹落盘：trajectories.jsonl 按 session_id 记完整对话 + tool_call/tool_result + 状态栏快照 + final conclusion + evidence 行 ID + as_of。③ langfuse 写回 trace（已核实 2026-10-01）：插件 `@langfuse/pi-observability-plugin` hook `tool_execution_start`/`tool_execution_end`，自建工具完整覆盖，trace 含工具名+参数(input,脱敏截断20K)+返回值(output,截断20K)+is_error+usage/成本+耗时；验证器分数+失败维度+成本 4 维度写回 trace 完全可行。④ HTTPS 回前端，用户可点踩（带 session_id 入库）。

badcase 回放：用户点踩 → 按 session_id 拉轨迹 → 区分"数据过期 vs 推理错 vs 工具选错"
