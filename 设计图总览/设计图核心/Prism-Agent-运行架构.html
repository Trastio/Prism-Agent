Prism-Agent 运行架构 · 讨论稿

一个底盘（pi）+ 两个黑盒供给端（口碑 / 舆情）+ Prism 自建语义插座。v0.5（2026-10-02：E5复审重核+商业北极星改DAU+v8→v11同步）。继承 v0.4：阿里云单台ECS 4c16g+峰值并发40、无登录+本地ID、Redis建议上非阻塞、读写分离、MCP桥退役。供讨论，非定稿。
表现层（自建） 编排层（pi harness） 语义层（Prism 核心资产） 供给层（黑盒·不动内部） 数据层 红线落点
一句话形态（2026-09-30 云真并发版）：Prism 不"搬"任何一个项目的代码。pi 当底盘（agent loop + 护栏）， 两个旧项目当"插头"（只读直连 / REST），Prism 自己只建中间那层"插座"—— 数据源注册表 + 口径视图 + TS 语义工具。表现层是自建双模式网站，pi 躲在 API 后面。 部署=阿里云单台ECS 4c16g单机起步+本地Nginx（峰值并发40，原多实例+SLB降级远期扩展项，工位机出局）；认证=无登录+浏览器本地ID（管理者操作弹密码）； 会话状态=Redis建议上非阻塞（进程崩溃恢复+扩展余量，内存会话+落盘快照可替代起步）；数据层=读写分离（生产库只读直连+运行时写独立存储）；MCP桥退役（TS工具直读库）。

Guardrail Hooks

pi.on("tool_call") 抛错=fail-closed 拦截；pi.on("tool_result") 改写结果。护栏在执行层，不在提示词——in-context agent 不可靠地自检注入。

依据:chapter2/prompt-injection/agent.py:268-277(D4运行时拦截) + chapter9/harness-safety-gate/safety_policy_gate.py:322(validate_tool_call); pi.on hook形态是Prism对教材validate模式的API化封装

"模型可提出完成，不能批准自己的完成"。submit_conclusion 走台账，n 与覆盖率绝不采信模型自报，服务端真值校验。

③工具接口层【红线核心】：3核心常驻(query_sales/reviews/config) + discover_tools按需加载(能耗/评分/事件/缺陷等,包住两项目能力=Atuohome 15 MCP工具稳定层+舆情21个dashboard GET;MCP桥退役走TS直读) + tool_call护栏(cc-safety-net+自建红线拦截) + expected_* + tool_result改写(grounding)分维度配阈值 | PM性:3核心工具=棱镜三维度物化,工具门控(setActiveTools)按阶段解锁——没查配置时销量工具不给,PM不会没看产品力就谈市场结果
