# Prism-Agent 登录门禁方案 v1

> 2026-10-15 定稿（用户拍板：统一口令门，全员密码 666666）｜ 性质：**鉴权洞的最小补丁** + 二次评估/迭代归因前置
> 关联：上线方案 v1（上云前补鉴权）／会话隔离实测 10-12（user_id 自报无鉴权边界）／记忆缓做触发器①

## 1. 背景与动机

- 现状：user_id 前端自报，无任何门禁——知道 URL 就能用任意身份进站
- 三条线共同指向：①badcase 回流找不到主人（轨迹无法按真人归因）②记忆缓做的硬阻塞 ③上云前必补
- 目标：**进站必须过密码门**；身份可归因；改动面最小（一个轻量 change 收掉）

## 2. 拍板记录

| 项 | 拍板 |
|---|---|
| 门禁形态 | **统一口令门**：所有用户必须输 用户名+密码 才能进入，密码全员统一 `666666` |
| 权限分层 | 不变（红线#3）：admin（管理者=用户本人）可编辑赋分/触发采集；其余用户名只读 |
| 密码存储 | 只存盐哈希，不存明文 |
| 上云升级路径 | 上云前换强密码 + HTTPS；个人密码制留 v2 |

## 3. 产品形态

1. 打开 prism-web(:5173) → 先见登录页（用户名 + 密码两个输入框）
2. 密码 ≠ 666666 → 拒绝，提示"密码错误"；用户名任意（用于轨迹归因与权限分层）
3. 密码正确 → 发签名 token（HttpOnly cookie，7 天有效）→ 进主站
4. 主站所有接口（chat / 会话历史 / 看板代理 / 导出 / abort）未带有效 token → 401 → 前端弹回登录页
5. user_id 从 token 服务端解出，**前端自报字段废弃**

## 4. 技术设计（最小面）

```
prism-web(:5173)            prism-api(:8002)                pi_gateway(:9200)
登录页 ── POST /auth/login ──→ 验盐哈希 → 签发 HMAC token ──→ 每请求校验 token
      ←── Set-Cookie HttpOnly ─   (users.json: name+role+pwhash)   解出 user_id 注入
```

- **users.json**（prism-api 数据目录，gitignore）：`[{username, role: admin|viewer, pwhash, salt}]`；共享密码 666666 哈希一次，全员共用；admin 按用户名白名单
- **token**：HMAC-SHA256 签名（密钥走 env，gitignore），载荷 = username + role + exp(7d)；cookie HttpOnly + SameSite=Lax
- **eval 通道**：runner 启动时先 `POST /auth/login`（eval 专用账号，凭据走 env）拿 token 再跑题——评估链路不断
- **网关**：校验失败一律 401，不区分"没带 token/过期/伪造"
- **不做的**：个人密码、验证码、HTTPS（本地阶段）、记住我、注销页（v1 只要能进门）

## 5. 诚实边界（写进方案防止误判）

- 共享密码解决"匿名自报"，**不解决"个人身份可信"**（知道密码可冒充任何用户名）
- 因此**记忆缓做触发器①仍为未绿**——记忆继续等强鉴权；但评估归因、会话归属、防爬虫级窥探，本方案已够用

## 6. 验收标准（全过才算完）

1. 未登录访问主站任意页 → 跳登录页
2. 错密码 → 拒绝并提示；对密码 → 进站，7 天内免登录
3. chat / 会话历史 / 看板 / 导出 / abort 全链路 401 保护（逐个实测）
4. admin 账号可编辑赋分，viewer 只读（现有权限行为不回归）
5. eval runner 自动登录 → 60 题全量跑通 1 题 smoke + 门禁 E2E 1 题
6. users.json 中无明文密码；token 密钥不在 git
7. web tsc 0 错 + build 过 + smoke 全绿

## 7. 排期与顺序

- **先行**（半天级）：登录门 → 多轮评估批（跑 E2E 时顺带验证真人账号归因）
- 开工走轻量十步（改动面小，但涉及鉴权属安全敏感，Step7 隔离审查不省）
