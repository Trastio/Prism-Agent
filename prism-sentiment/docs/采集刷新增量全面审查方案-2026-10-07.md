## 二、发现的问题（修正后）

### P0（保留，唯一真隐患）：`trigger_collection` 函数内 import 致 UnboundLocalError

**位置**：[collection.py:166](file:///C:/Users/<you>/Desktop/Agent项目/Vehicle%20Sentiment%20Analysis%20Board/api/routes/collection.py#L166)、[collection.py:179](file:///C:/Users/<you>/Desktop/Agent项目/Vehicle%20Sentiment%20Analysis%20Board/api/routes/collection.py#L179)

**根因**：顶部 L5 已 `from datetime import date, datetime, timedelta`；但 L166 在 `if cs and cs.is_running:` 块内、L179 在 `else:` 块内**各有一处函数级 import**。Python 作用域规则：函数内任何位置出现对 `datetime` 的 import，该名字在整个函数内即为局部变量，遮蔽顶部导入。**关键在于"import 所在分支 ≠ 使用所在分支"**：

```
if cs and cs.is_running:            # L165  ← 风云T9L 走不到这里（is_running=False）
    from datetime import datetime, timedelta   # L166 ← 因此不执行
    ...
if cs:                              # L174  ← 命中
    cs.lock_acquired_at = datetime.now()       # L176 ← datetime 从未绑定 → UnboundLocalError → 500
else:
    from datetime import datetime   # L179 ← 另一分支
```

**影响面（精确化）**：仅当该车**已存在 `collection_status`（source="all"）行且 `is_running=False`** 时 500——即"空闲车型点采集必失败"，覆盖面≈所有采过的车。

| 场景 | 走向 | 结果 |
|---|---|---|
| 有行、`is_running=False` | 跳过 L166 块 → L174 → L176 | ❌ **500**（风云T9L） |
| 有行、`is_running=True` 且未过期 | L166 块 → L171-172 `return already_running` | ✅ 200 |
| 有行、`is_running=True` 且过期 | L166 执行 import → L176 可用 | ✅ 200 |
| 无行（新车） | `else` 分支 → L179 先 import | ✅ 200 |

**修复**：删 L166 与 L179 的函数内 import，统一用顶部 L5 导入。

**逻辑不变性说明**（遵守"保留原逻辑"）：删除后 L170 (`datetime.now() - lock_time`)、L176、L181 均使用顶部 `date/datetime/timedelta`，脏锁容错与分支行为完全不变，仅消除遮蔽。

**回归测试（新增要求）**：`tests/` 增加一个用例——构造"已有 cs 行且 is_running=False"的车辆调用 `trigger_collection`，断言返回 200（`status=started`）而非抛 `UnboundLocalError`。这是 v1 缺失的、能挡住本次回归的关键测试。

## 二·补、已证伪的 v1 结论（含证据）

### ❌ v1 P1-1：`triggerCollection` already_running 不复位 loading → "永久 disabled"

**证伪**：`triggerCollection`（L1230-1239）在 `already_running` 后确实未复位 `loading`，但紧接着调用 `_startPolling()`；轮询函数 `_pollPipeline` 在到达终态时**会复位**：

```javascript
if (data.phase === "completed" || data.phase === "error") {   // app.js:1262
    clearInterval(this.pipelinePollTimer);
    this.pipelinePollTimer = null;
    this.loading = false;                                     // app.js:1265
    ...
```

即 `loading` 会在"在跑的那条管线结束"时复位——这正是期望行为，**不是永久 disabled**。v1 的"永久"结论不成立。

### ❌ v1 P2-1：already_running 后仍调 `_startPolling`

**不成立**：调用 `_startPolling` 是**有意**的（观察在跑任务进度），且由 `_pollPipeline` 终态负责复位 `loading`。
**且与 v1 P1-1 互相耦合、自相矛盾**：若按 v1 P2-1 的"加 `return`（不调 `_startPolling`）"实现，则 `loading` 再无复位点 → 才真会"永久 disabled"，此时又必须按 v1 P1-1 补 `loading=false`。v1 把二者当作独立问题提出，逻辑不闭环。
**本版裁定**：**保持现状（继续轮询）**，不做改动；若确要提前结束轮询，则必须"加 return **并**显式 `loading=false`"二者同时做。**（用户已确认：保持现状，不改动。）**

### ❌ v1 P1-3：`dashboard.py` / `analysis.py` 同类 UnboundLocalError 隐患

**证伪**：判据是「import 分支 ≠ 使用分支」。逐一核对，这些位置的 import 与使用**在同一分支内**，凡到达使用点的路径都先执行了 import，**不会 UnboundLocalError**：

| 位置 | 结构 | 结论 |
|---|---|---|
| `dashboard.py:892,893` | `if start:` 内 import → 同行块内 `dt.fromisoformat(start)` | ✅ 安全 |
| `dashboard.py:896,897` | `if end:` 内**各自再 import** → 同行块内使用 | ✅ 安全（v1 所设"start 空/end 非空"场景在 L896 有独立 import） |
| `dashboard.py:991,992` | `if start:` 内 import → 同行块内使用 | ✅ 安全 |
| `dashboard.py:994,995` | `if end:` 内 import → 同行块内使用 | ✅ 安全 |
| `dashboard.py:688,689` | 函数体**无条件** import → 紧接使用（`get_sentiment_trend`，其前无 `datetime` 使用） | ✅ 安全 |
| `analysis.py:79-81` | `try:` 内 import → 同行块内使用 | ✅ 安全 |

故 v1 P1-3 的"同类隐患"表述**不准确**，降级为 P3 风格清理。（注：v1 列的行号亦有误——`dashboard.py:894` 实为 `896`。）
