# 车型舆情情感分析看板 —— 项目架构

> 2026-09-13 依据真实代码与运行状态梳理。技术定位：**多平台社媒+新闻的车型舆情监测系统**，
> 采集→分析→聚合→看板四层，全部单机自包含（一个 Python 进程 + SQLite + 静态前端页）。

---

## 1. 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| **运行环境** | Python 3.13（conda base，全路径启动） | Windows 单机；`start.py` supervisor 常驻 |
| **后端** | FastAPI + uvicorn | 端口 8000；lifespan 预热车系索引（7138 车系，车型联想用） |
| **数据库** | SQLite（aiosqlite + SQLAlchemy 2.0 async） | `data/vehicle_sentiment.db` 单文件 |
| **前端** | Vue 3（CDN 引入，**无构建步骤**）+ ECharts + wordcloud | 单页 `frontend/index.html` + `static/js/app.js`，FastAPI 直接托管 |
| **云端 LLM** | GLM-4-flash（智谱，.secrets 配置） | 帖子情感/维度分析、事件命名、评论摘要、关键词扩词 |
| **本地模型** | Qwen3-4B LoRA（transformers + torch） | 评论 ABSA（15 维度情感），免费本地推理 |
| **分析算法** | jieba 分词、networkx 关键词共现图、python-louvain 社区检测、simhash 近重复去重、trafilatura 新闻全文抽取 | 事件检测与去重 |
| **测试** | pytest + pytest-asyncio | **647 用例全绿**（含 4 平台契约复刻 fixture） |
| **采集** | httpx 异步（TikHub/OneAPI/anspire/bocha 全 API 化，CDP 浏览器已退役） | 供应商见 §3 |

## 2. 四层数据流（端到端）

```
┌─────────────────────────── 采集层 scheduler.py ───────────────────────────┐
│                                                                            │
│  新闻: anspire(主) + bocha(备) + tavily      ── 全关键词，无登录            │
│  社媒: TikHub ──微博(搜索/评论/详情) 小红书(搜索/评论) 快手(搜索/评论)       │
│        OneAPI ──抖音搜索(主，¥0.03/词)                                      │
│        TikHub ──抖音评论+批量统计 + 【空窗备胎】OneAPI 0帖时自动回退搜索     │
│  指数: TikHub douyin/index(30天滚动窗) + 小红书PGY(固定91天)                │
│                                                                            │
│  关键词: search_keywords(核心词) + LLM扩词(10个/车, 缓存7天) → 每平台取5词   │
│  窗口:   首采90天 / 增量=上次采集→现在(漏跑自动补)；指数固定30天滚动         │
└──────────────────────────────┬─────────────────────────────────────────────┘
                               ▼
┌─────────────────────────── 入库层（防重复四道闸）─────────────────────────┐
│  ① URL路径去重(query是凭证非身份, xsec_token变体拦截)                      │
│  ② 新闻标题归一去重(跨源转载同稿)                                          │
│  ③ 品牌词过滤(竞品帖) + 作者分层打标(官号/4S/媒体/用户) + 时间窗floor      │
│  ④ 评论两级去重(平台评论id优先 / 内容指纹兜底)                             │
│  老帖再搜到 → 互动数(赞/评/转)刷新                                          │
└──────────────────────────────┬─────────────────────────────────────────────┘
                               ▼ raw_posts / post_comments / search_index_metrics
┌─────────────────────────── 分析层 batch_runner + analyzer ────────────────┐
│  帖子: GLM 情感(正/中/负) + 15维度打分 + subject标注(self/竞品) + 事件标签   │
│  评论: 本地Qwen3-4B ABSA(dim_sentiment, 零分=中性提及) + GLM评论摘要       │
│  事件: LLM话题标注 → jieba关键词 → 共现图 → Louvain社区 → 时间切片(7天)     │
│        → LLM命名 → 同名相邻切片合并(≤14天) → 全量重建(先删后建)             │
│  全文: 新闻 trafilatura 抽正文；微博长文 详情端点回填                       │
└──────────────────────────────┬─────────────────────────────────────────────┘
                               ▼ analyzed_posts / event_groups
┌─────────────────────────── 聚合层 heat_calculator ────────────────────────┐
│  每日: discussion(社媒评论Σ) / media(新闻帖数) / interaction(互动加权)      │
│  幂等重算(非累加)；attention无指数时由互动合成兜底                          │
└──────────────────────────────┬─────────────────────────────────────────────┘
                               ▼ heat_metrics
┌────────────── API 层 (FastAPI, /api/*) ──────────────┐   ┌────────────────┐
│  dashboard: overview/趋势/情感/维度/热帖/事件/词云…   │   │ 前端 Vue3 单页 │
│  指数合成: 两源窗口内归一0-100平均(search_index)      ├──▶  四层递进:      │
│  vehicles: 车型管理/联想(autohome)                    │   │ KPI→趋势→归因 │
│  dialog: 锚点对话(SSE)  reports: 舆情报告             │   │ →内容 + 对话   │
└──────────────────────────────────────────────────────┘   └────────────────┘
```

## 4. 数据库表（SQLite, 10 张）

| 表 | 内容 | 写入方 |
|---|---|---|
| `vehicles` | 车型（核心词/扩词/状态 active·paused） | API |
| `raw_posts` | 原始帖（URL/平台/互动数/全文/author_type 分层） | 采集 |
| `analyzed_posts` | 分析结果（情感/维度/subject/摘要/事件标签） | 分析 |
| `post_comments` | 评论（cid 去重键/dim_sentiment） | 采集+分析 |
| `event_groups` | 事件（social/news 两源，先删后建） | 事件检测 |
| `heat_metrics` | 每日热度四指标（每车每天一行） | heat_calculator |
| `search_index_metrics` | 多平台搜索指数（vehicle×date×source） | IndexCollector |
| `collection_status` | 采集状态/时间（mode 判定依据） | scheduler |
| `reports` / `vehicle_groups` | 舆情报告 / 分组对比 | 闲置中 |

### Prism-Agent 对接契约（2026-09-15 拍板：REST，不做 MCP）

- **对接面**：Prism 的 TS 语义工具薄封装 `http://<舆情服务>/api/dashboard/*`（只读）。
  端点：overview / trend / sentiment-trend / platform-distribution / event-distribution /
  top-posts / posts / events / dim-sentiment / word-cloud / competitor-comparison /
  comment-sentiment-diff / **dim-examples**（维度→帖+评论实例）/ **post-comments**（单帖评论）。
- **不做 MCP 的理由**：pi-mcp-adapter 定位是 Atuohome 存量工具过渡桥（护栏拦截未验证）；
  精选语义工具须做在 TS 原生侧（hooks/telemetry/evals 可见）；40 人并发 stdio 每会话
  一 MCP 进程 × SQLite 单写锁；HTTP 最可移植。
- **分工**：舆情=数据生产侧（管线+cron），Prism=消费侧（查询/展示/agent）。
  上云时舆情成 sidecar 服务 + DB 迁 PostgreSQL，pi 工具不变（仍走 REST）。
- **口径注意**：情感分布/健康分/维度口碑自 2026-09-15 起排除官方与经销商作者
  （`AUTHENTIC_AUTHOR`，author_type 分层）；热帖/声量保留全部并打"官/商"徽标。

**成本口径（实测）**：每车每轮日级增量 ≈ ¥6~10（小红书评论占 60%）；4 车日更 ≈ ¥800~1200/月。
**频率**：日级增量为主（窗口自愈），指数 30 天滚动，热度每日幂等重算。

## 安全边界（2026-10-06 补，audit Phase 6 T6.8）

- **默认内网**：`start.py` 默认绑定 `127.0.0.1`，仅本机访问。
- **`HOST=0.0.0.0` 风险**：一旦设为 `0.0.0.0` 即对外完全开放，**无鉴权 / 无 CORS 配置**，含写副作用端点（`/api/vehicles/{id}/collect` / `/api/analysis/trigger` / `/api/dashboard/reports`），等同任意人可触发采集（烧 TikHub 余额）或读数据。
- **开放外网前必须**：① 加鉴权中间件（至少对写副作用端点）；② 配置 CORS 白名单；③ 评估 TikHub key 暴露风险。
- **密钥管理**：`.secrets` / `.env` 读取，未硬编码，日志不打印密钥。
