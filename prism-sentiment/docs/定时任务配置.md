# 定时任务配置

`scripts/daily_update.py` 是舆情看板的每日更新入口（prime-agent 层）。本文档说明如何在 Windows / Linux 上配置定时执行，以及推荐的执行策略。

## 推荐执行时间

- **每天 02:00** 跑一次 `--all`（凌晨避开社媒平台高峰、API 限流宽松、看板无人在看）。
- 单车超时默认 30 分钟；21 车时代若全跑满需 ~10 小时，建议凌晨起步刚好赶早高峰前收尾。
- 备份在脚本收尾自动执行（`utils/backup.py` 滚动保留），无需另配。

## 命令

```bash
python scripts/daily_update.py --all
```

环境要求：
- Python = `C:/Users/<you>/anaconda3/python.exe`（conda base，项目环境）
- 工作目录 = 项目根 `Vehicle Sentiment Analysis Board`
- 服务须在运行（`start.py` supervisor 常驻；先跑 `启动看板.bat` 或 `start.py`）

完整命令（Windows 计划任务用）：

```bat
cd /d "C:\Users\<you>\Desktop\Agent项目\Vehicle Sentiment Analysis Board"
"C:\Users\<you>\anaconda3\python.exe" scripts\daily_update.py --all
```

## --all 频率分层（控成本）

不是每车都日更，按近 30 天帖数分三档：

| 档位 | 阈值（近30天帖数） | 频率 |
|------|---------------------|------|
| hot  | > 100               | 日更（每天跑） |
| mid  | > 30                | 隔日（偶数日跑） |
| cold | ≤ 30                | 周更（仅周一跑） |

分层依据 = 近 30 天 `raw_posts.collected_at` 计数（同步 sqlite3 直查）。查询失败时按 cold 兜底（不阻断主流程）。脚本启动时会打印 `[FREQ] 频率分层跳过 N 车: 名称(档位)...` 一行，便于核对。

## Windows 计划任务

### 方式 A：schtasks 命令（推荐）

以管理员身份打开 cmd，执行：

```bat
schtasks /create /tn "VehicleDailyUpdate" /tr "cmd /c cd /d \"C:\Users\<you>\Desktop\Agent项目\Vehicle Sentiment Analysis Board\" && \"C:\Users\<you>\anaconda3\python.exe\" scripts\daily_update.py --all >> logs\daily_update.log 2>&1" /sc daily /st 02:00 /f
```

参数说明：
- `/tn` 任务名；`/sc daily` 每天；`/st 02:00` 起始时间
- `/f` 强制覆盖同名任务
- `>> logs\daily_update.log 2>&1` 把输出追加到日志（需先确保 `logs\` 目录存在）

查看 / 删除：
```bat
schtasks /query /tn "VehicleDailyUpdate" /v
schtasks /delete /tn "VehicleDailyUpdate" /f
```

### 方式 B：图形界面

1. Win+R → `taskschd.msc` → 回车，打开「任务计划程序」
2. 右侧「创建基本任务」→ 名称填 `VehicleDailyUpdate` → 下一步
3. 触发器选「每天」→ 开始时间 02:00:00 → 下一步
4. 操作选「启动程序」
   - 程序或脚本：`C:\Users\<you>\anaconda3\python.exe`
   - 添加参数：`scripts\daily_update.py --all`
   - 起始于：`C:\Users\<you>\Desktop\Agent项目\Vehicle Sentiment Analysis Board`
5. 下一步 → 勾选「完成后打开属性对话框」→ 完成
6. 属性里：
   - 「不管用户是否登录都要运行」勾上
   - 「使用最高权限运行」勾上
   - 「操作」标签确认参数与起始于目录无误

## Linux cron

`crontab -e` 加一行（每天凌晨 2 点）：

```cron
0 2 * * * cd /path/to/Vehicle\ Sentiment\ Analysis\ Board && /usr/bin/python3 scripts/daily_update.py --all >> logs/daily_update.log 2>&1
```

注意路径按实际部署位置替换。

## 日志与排障

- 日志默认追加到 `logs/daily_update.log`（首次配置前先 `mkdir logs`）
- 脚本退出码：`0`=全部成功；`1`=部分车失败或备份失败；`2`=服务不可达；`3`=无待更新车辆
- 若退出码 = 2：先确认 `start.py` 服务在跑（`curl http://127.0.0.1:8000/api/vehicles`）
- 若退出码 = 3 且用了 `--all`：检查 `vehicles` 表是否有 `status='active'` 的车，以及频率分层是否把全部车跳过（如非周一且全是 cold 档）

## 手动触发（绕过定时）

需要立刻跑某车时，不用等定时：

```bash
# 单车
python scripts/daily_update.py --vehicle M03

# 强制全车（忽略频率分层）
python scripts/daily_update.py --vehicle ""
```

注意：不加 `--all` 且 `--vehicle` 为空 = 全部 active 车全跑（不分层），适合需要立刻全量刷新的场景。
