## 八、设计缺陷（影响观感和专业度）

| # | 问题 | 具体表现 | 建议 |
|---|------|----------|------|
| F8 | **Header 按钮过多且无层级** | 搜索、分组、时间、+分组、+车型、采集、分析、状态挤在一行，视觉混乱 | 核心操作与辅助操作分两组，辅助操作收进"..."下拉 |
| F9 | **页面太长，缺乏焦点** | 10+ 个 section 垂直堆叠，用户需要大量滚动才能看到底部内容 | 折叠次要section（异常、事件时间线默认折叠），或用Tab切换 |
| F10 | **概览区信息密度仍不够** | 3栏中左栏只有总量+健康度，中间只有环形图，有效信息只有5-6个数字 | 合并为紧凑卡片行，加情感条形图 |
| F11 | **分析区三栏图表过于拥挤** | 3个280px高的图表挤在一行，鼠标 tooltip 被相邻图表遮挡，横向柱状图标签被截断 | 改为2栏布局或 Tab 切换，给每个图表足够宽度 |
| F12 | **平台声量分布用环形图不合适** | 5个平台中有2-3个声量很小，环形图扇区太窄看不清 | 改为横向柱状图，与其他分布图风格统一 |
| F13 | **报告区预览内容过长** | `reportPreview` 显示120字符但 Markdown 格式去掉后仍是一大段文字，卡片过高 | 限制为2行，加 `line-clamp: 2` |
| F14 | **空状态文案单调** | 所有空状态都是"暂无XXX"，没有引导用户操作 | 例如"暂无异常 — 运行分析后自动检测" |
| F15 | **异常时间线和事件时间线视觉无区分** | 两个独立section里都有时间线概念，用户困惑为什么有两个 | 合并为一个"异常&事件"section，用Tab或折叠切换 |
