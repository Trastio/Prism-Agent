## 二、v3 新增的关键发现（v1 没有，本次更新补全）

### 新增 1：§8.1 小红书 400 重试风暴（高）
- **根因**：`tikhub_collector.py:291` `if not upstream_flaky and not endpoint.startswith("xiaohongshu.")` 让小红书豁免 → 永久 400 也走 5 次重试。叠加 `max_keywords=15` → 单平台最坏 75 次请求，十几分钟假死。
- **修复**：让 xhs 永久 400（`code=-1`）识别为请求级永久错误、不重试（与其他平台一致）。
- **修正我之前的判断**：不是"跳过失败平台"（try/except 已齐），是"停止无效重试"。

### 新增 2：§8.2 关键词扩展失败固化 7 天（高）
- **根因**：`keyword_expander.py:82-84` LLM 失败 `return base_keywords`，`scheduler.py:176-181` 无条件落库 + 置 `keywords_expanded_at=now`，`scheduler.py:156-160` 缓存判据 `elapsed < 7` 直接返回失败结果。
- **影响**：采集窄化 7 天无人知。
- **修复**：失败不落库 / 不置 `keywords_expanded_at`，或加 `expansion_status` 字段区分成功失败。

### 新增 3：§9.3 评论情感分母把未分析评论计成中性（高）
- **根因**：`dashboard.py:462-466, 502-509` 对每条评论调 `derive_comment_sentiment`，NULL/`"{}"` 返回 neutral 且 `counts[s]+=1`。
- **影响**：Phase6 未跑或失败的评论 → neutral 虚高、total 失真（与 H2 叠加放大）。
- **修复**：分母排除未分析评论，或显式标记 `unanalyzed_count`。

### 新增 4：§9.4 事件"7天切/14天并"互相抵消（中）
- **根因**：`event_tracker.py:48` 切分 7 天、`:365` 合并 14 天 → 净有效间隔 14 天，`_TIME_SPLIT_DAYS=7` 形同虚设。
- **修复**：切分与合并参数统一，或合并阈值 ≤ 切分阈值。

### 新增 5：§9.5 DefectTheme TTL 注释与实现不符 + 不写 window 字段（低，但与 H1 叠加）
- **根因**：docstring 写 24h（`dashboard.py:1574`），实际 `21600s=6h`（`:1590`）；Phase9 落库不写 `window_start/end`（`collection.py:96`），端点 TTL 判据要求窗匹配 → 带窗请求必重算烧 LLM。
- **修复**：Phase9 落库时写 `window_start/end`；TTL 注释改为 6h 或实际改 24h。与 H1 时区一起修。

### 新增 6：§11.1 ECharts 空↔有数据切换白图（高，用户可见）
- **根因**：`app.js:578-585` 空数据分支抹掉 canvas，重渲染分支因实例仍存在跳过 `init` → 写入已脱离 DOM 的 canvas → 空白。
- **遍布**：`app.js:580,610,821,874,930,981`（8 处图表）。
- **复现**：切零数据车（元UP）→ 切有数据车（星愿）→ 图表白屏需刷新。
- **修复**：空数据分支用 `chart.clear()` 不抹掉 canvas，或重渲染前 `dispose()` 旧实例。

### 新增 7：§13.2 H3 分母不同源量化（影响面比此前估计大）
- **实测**：星愿差 23%、风云T7 19.4%、零跑B10 20.7% — 用户在"结论先行"层看到「舆情总量 1138」与环图合计 876 对不上账，缺口 23%。

### 新增 8：§10 dialog/agent 模块未落地（不是问题，是未开工）
- 只有表/CSS/spec 残留，无后端路由/前端脚本。memory [[vehicle-sentiment-agent]] 归档 spec 确认是前瞻设计未实现。
- **不需修复**，未来补接时挂全口径常量 + 复用 renderMarkdown。
