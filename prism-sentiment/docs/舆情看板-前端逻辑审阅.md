## 一、产品定位与双模式

**一句话**：品牌方打开页面 30 秒内读完「态势 → 归因 → 证据」，传播团队拿到「今天该盯什么」的行动清单。

页面顶部 `view-switch` 切换两种人格（互斥）：

| 模式 | 视角 | 回答的问题 | 载体 |
|---|---|---|---|
| **监控看板**（默认） | PM/市场 | 「现在舆情怎么样？为什么？」 | 01-06 六区 + 分组对比 |
| **传播点报** | 传播团队 | 「今天有哪些点要处理/借力？」 | 点卡片 feed |

切模式是纯前端 `v-if` 切换，同一份数据两个视图——不是两套系统。

## 二、页面主干流程（打开后发生什么）

```
打开 127.0.0.1:8000
  → 车型 combobox 联想（汽车之家车系，300ms 防抖，杜绝手填错车）
  → 选中车型 onVehicleChange()
      → Promise.all 并发拉 14 个端点（overview/趋势/维度/事件/平台/热帖/
        负面雷达/词云/采集状态/进度/全部帖/争议帖…）
      → $nextTick 内逐图渲染 echarts
      → 若当前是点报模式：PointsUI.load() 单独拉点
  → 换车型 / 改时间窗（7/30/90/180天/全部，默认30天）→ 全量重跑上面这套
```

两条**刻意不带时间窗**的例外：热帖 TOP5 和词云——微博/抖音老帖 `published_at` 为 NULL，带窗会静默丢帖（代码有注释，是有意保留的坑，勿"修"）。

## 三、监控模式六区（信息四层递进：结论→趋势→归因→证据）

### 01 · 舆情全景 ——「30 秒态势」
8 张 KPI 卡 + 情感环形图。关键口径：
- **健康分** = 50 +（正面−负面）/已分析帖×50，分母只算已分析的自提及帖（防止无关帖稀释向 50 偏）
- 搜索热度 = 抖音+小红书合成指数近 30 日百分位
- 声量节奏 = 周环比箭头（封顶 999%，防小基数 3000% 噪音）
- 情感环点击扇区 → 锚点对话下钻

### 02 · 情感分析 ——「趋势与口碑结构」
- 情感趋势：ISO 周堆叠柱（近 8 周，周一为界），点击某周下钻
- 正向情感得分：15 个 ABSA 维度横条（0-1），一眼看出强项弱项

### 03 · 负面雷达 ——「有没有雷」（负面是第一视野，独占固定扫读位）
自上而下四层：
1. **风险横幅**：一行读完档位（🟢低/🟡中/🔴高/⚪样本不足）+ 归因理由。服务端三因子判定（负面率/周环比/吐槽影响力分），样本 <20 直接判"样本不足"防虚报。
2. **非对称双栏**：左宽栏 = 高影响吐槽榜 TOP10（负面帖按影响力分 `▲×1+💬×5+转发×10` 排）；右窄栏 = 负面维度 TOP5 + 负面事件 TOP3。
3. **负面声量趋势**：周负面帖柱 + 负面占比折线（右轴自适应不写死）；⚠ 标注 = 周环比 ≥50% 且本周 ≥3 帖。
4. **口碑反转卡**（cap 5 张）：评论区与主帖情感背离的帖——正→负「好评翻车」🔴 排前 / 负→正「差评反转」🟢 / 其他「情感错位」⚪；每卡带评论数、痛点 chips、热门评论摘录、一句话动作。

### 04 · 热度追踪 ——「传播面有多大」
搜索指数周均线（p95 截尾防毛刺）+ 社媒讨论 vs 媒体报道双线 + 平台声量分布 + 热帖 TOP5（tabs：全部/吐槽/四平台）。

### 05 · 事件脉搏 ——「聚成了哪些事件」
事件时间线（social/news/all 三 tab）：事件卡带帖数、起止、摘要、情感分布；点击进锚点对话。旁边观点标签 TOP10 = 用户真实看法词。（原"事件标签分布"图已删——与时间线重复。）

### 06 · 内容洞察 ——「原始语料」
关键词云（原生 canvas，relevant 帖标题+正文 jieba 词频）+ 舆情简报（点击生成，LLM）。

### 方法论区
数据来源/管线/健康分公式的自解释文案——口径改了这里必须同步。

## 四、点报模式 ——「行动点 feed」

数据源 `GET /api/dashboard/points/{vid}`，后端按新鲜度排，前端按热度（volume+证据互动）重排。

- **页头摘要**：在榜 N 点：X 宣传 · Y 防守｜🆕/🔥/❄️ 状态分布
- **筛选**：全部 / 🟢宣传 / 🔴防守（缺陷 chip 是 defect-theme 方案要加的，现在还没有）
- **点卡片**：类型/状态/在榜天数 → 一句话主张 → 指标行 → 证据链（代表评论 + 前 3 证据帖可点开详情；author 空 = LLM 转述会标注「（模型转述）」）→ 建议动作 → 问 AI
- **点生命周期**（后端纯规则状态机）：`new → active(声量≥昨日×1.2，🔥发酵中) → cooling(连续2日<×0.8) → archived(3日未匹配)`
- 点报**无时间窗**——生命周期本身就是时间语义，顶部时间预设对它不生效

## 五、贯穿全站的三套机制

### 1. 口径三挂（哪里都生效，副标题透明标注）
| 口径 | 含义 |
|---|---|
| RELEVANT_ONLY | 无关帖（irrelevant）不进任何声量/榜/词云 |
| AUTHENTIC_AUTHOR | 情感/口碑类图排除官方、经销商帖（副标题写明「已排除官方/经销商」） |
| SELF_ONLY | 只算主车型帖，竞品帖不算 |

### 2. 锚点对话（全站统一下钻出口）
任何图表点击 → `openDialog(类型, 数据)` → 右侧滑出对话面板，服务端按锚点类型（trend/event/sentiment）聚合上下文喂 LLM。点报卡的「问 AI」也走这里（point 锚点 = 点详情+证据帖+代表评论）。

### 3. 采集可见性
chrome 条上有采集按钮 + 管线状态点（采集/分析/完成/错误四色）；采集面板展示 env_warning（如 TikHub 402 断供）+ 分平台 chips——社媒哪个平台跳过/失败不再静默。

## 六、浮层与辅助面板

全部帖子（筛选+分页）/ 历史报告（周报深报点击生成）/ 帖子详情 Modal（15 维情感条+评论摘要证据链）/ 添加车型 / 新建分组 / 分组对比（多车卡+情感对比/维度雷达/声量趋势）。

## 七、已知取舍（有意为之，非缺陷，审阅时别当 bug 报）

1. 单文件 app.js ~1300 行不拆——零构建原则（Vue3 CDN + ECharts vendor，无 npm/webpack），改完刷新即生效，代价是手动 `?v=N` cache-bust
2. Vue 钉死 3.4.38 不升级——浮动 tag 曾漂到 3.5.43 踩坏锚点对话（实雷）
3. 热帖/词云无时间窗——NULL published_at 丢帖问题
4. 列表区 cap（反转卡 5 张/点卡证据 3 帖）——超视口长列表会触发全局 resize mid-render 崩 echarts（cap5 不崩 cap6 崩，二值实验钉的）
5. 无实时语义——日级采集撑不起，告警条/实时大屏明确不做
6. 点报无环比展示——neg_wow 后端算了没上前端（终审 Minor #3，polish 批次待办）

## 八、审阅关注点（建议你重点看这几处）

1. **六区顺序与信息密度**：负面雷达放 03 独占固定位是否符合你的扫读习惯？还是应该更靠前（如 01 后直接雷达）？
2. **点报状态机阈值**：active=×1.2 / cooling=×0.8 / archived=3天——日级数据下这个节奏对不对？
3. **KPI 八卡**：哪几张你实际从来不看？（砍卡比加卡便宜）
4. **cap=5 的反转卡**：超过 5 张的反转帖静默截断——要不要加「查看全部」入口？
5. 缺陷话题方案（见 `docs/缺陷话题监控-方案说明.md`）落地点报后的 chips 会变成 全部/宣传/防守/🔴缺陷——与现有筛选逻辑的直觉是否一致？
