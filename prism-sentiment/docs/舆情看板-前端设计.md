## 1. 产品定位与设计原则

**一句话**：让品牌方（市场助理视角）打开页面 30 秒内读完「态势 → 归因 → 证据」。

四条贯穿性原则（历轮改版沉淀，新功能必须遵守）：

1. **四层递进**：KPI 态势 → 趋势 → 归因 → 内容证据。信息从"结论"到"原始帖"逐层展开，任何图表点击都能下钻到帖子级证据链。
2. **负面是第一视野**：负面雷达独占 03 区固定扫读位——"有没有雷"先于"整体怎么样"。
3. **零构建**：Vue 3 CDN 全局构建 + ECharts vendor + 原生 CSS，无 npm/webpack。改完刷新即生效，代价是靠 `?v=N` 手动 cache-bust。
4. **口径透明**：凡是做了口径排除的图，副标题必须写明（如"已排除官方/经销商"），不让用户对不上数。

**明确不做**（历史拍板，勿翻案）：竞品面板、KOL/作者画像、实时告警推送（日级采集撑不起）、采集漏斗、阈值配置 UI。

## 2. 技术底座

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Vue 3 `vue.global.prod.js`（CDN） | 单文件 Options API，`#app` 一个根实例，无路由无组件拆分 |
| 图表 | ECharts 5（`/static/vendor/`） + 原生 canvas 词云 | `echarts-wordcloud@2.1.0` 与 echarts5 不兼容已弃用 |
| 样式 | 单文件 `style.css`，CSS 变量主题 | `--neg/--negative-bg/--accent/--muted` 等；Inter + Noto Sans SC |
| 传输 | `apiFetch()` 封装 fetch | `{json}` 选项自动序列化；`{silent:true}` 抑制 toast（轮询/联想类高频调用） |
| 错误 | Toast 容器（右上角） | error 红，自动消失 |

**缓存纪律**：`index.html` 由后端 `Cache-Control: no-store` 返回（否则 Chrome 硬缓存导致新 `?v=` 永远不生效）；`app.js`/`style.css`/`points.js` 改动必须递增 `?v=`（当前 app.js v27 / style.css v20 / points.js v3 / dialog.js v10）。**Vue 必须钉具体版本**（现 3.4.38）——unpkg 浮动 tag 漂移到 3.5.43 后 `app._instance` mounted 即 null，踩坏锚点对话（2026-09-21 实雷；修复=钉版 + `window.__vmProxy` 根代理，dialog.js getRootVm 优先取它）。

## 4. 各 Section 设计

### 01 · 舆情全景 —— 8 KPI + 情感环
`panorama-grid`：左 8 张 KPI 卡（2×4），右情感环形图。

| KPI | 语义 / 口径 |
|---|---|
| 健康分 | 50 +（正−负）/已分析×50；**分母=已分析 self 帖**（09-13 修：用全部帖会稀释向 50 偏） |
| 舆情总量 | relevant 帖数 + 已分析数 + 均评 |
| 情感占比 | 正面率主值，负面/中性进 desc |
| 搜索热度 | 合成搜索指数（抖音+小红书），近 30 日百分位 |
| 讨论声量 | 日均评论（社媒评论 + 新闻帖） |
| 事件聚类 | 总数，社媒/新闻拆分 |
| 声量节奏 | 周环比箭头（封顶 999%）+ 峰值日 |
| 维度亮点 | 最强/最弱维度 |

情感环：点击扇区 → 锚点对话 `sentiment` 分支。副标题「用户口碑 · 已排除官方/经销商」。

### 02 · 情感分析
- **情感趋势**：ISO 周（周一起）堆叠柱，近 8 周，正/中/负三层；点击柱 → `trend` 锚点。
- **正向情感得分**：15 维横条 0-1，色深映射分值；数据源 `dim-sentiment`（口碑口径）。

### 03 · 负面雷达（2026-09-16 新增，排版 v2）
自上而下：

1. **风险横幅**（`risk-banner`）：一行读完——左侧档位色边+色点（🟢low 绿 / 🟡medium 琥珀 / 🔴high 红底渐变 / ⚪insufficient 灰），中间档位名+归因理由（服务端可解释三因子：负面率/周环比/TOP 吐槽影响力分，样本 <20 直接判"样本不足"防虚报），右侧三数（负面声量 / 负面率 / 周环比箭头，负面涨=红 ▲）。
2. **非对称双栏**（`radar-grid: 1.7fr 1fr`）：
   - 左（宽）：**高影响吐槽榜 TOP10**——`sentiment=negative × 影响力分（▲×1+💬×5+→×10）`，行内平台徽标+官/商标+最负 2 维 chips，点击开帖子详情。
   - 右（窄竖栈）：**负面维度 TOP5**（负面帖数/负面率红渐变横条，点击 → 负面锚点对话）+ **负面事件 TOP3**（按事件内负面帖数排）。
3. **负面声量趋势**（全宽）：周负面帖柱 + 负面占比折线（右轴**自适应** 0~max×1.25，勿写死 100%）；⚠ 标注 = 周环比 ≥50% 且本周 ≥3 帖（小基数防噪）。
4. **口碑反转卡**（全宽；原「争议帖预警」2026-09-22 重做）：按 direction 分型——正→负=🔴好评翻车（排序优先，红）/ 负→正=🟢差评反转（绿）/ other=⚪情感错位；每卡 = 评论数 + genuine_themes 痛点 chips + top_comment 热门评论摘录 + 一句话动作行；**cap=5**（超视口长列表触发全局 resize mid-render 崩 echarts，2026-09-21 实雷）。数据源 comment-sentiment-diff（含 direction/comment_count/top_comment/platform）。

数据源：单端点 `GET /api/dashboard/negative-radar/{vid}`（KPI/榜/维度/事件一次聚合）+ 复用 `sentiment-trend`（趋势）+ `comment-sentiment-diff`（争议）。

### 04 · 热度追踪
- **搜索热度**：合成指数周均折线（p95 截尾防毛刺），点击 → `trend` 锚点。
- **讨论与传播**：社媒讨论（实线）+ 媒体报道（虚线）双线。
- **平台声量分布**（relevant 口径）+ **热帖 TOP5**：tabs = 全部/吐槽/四平台；吐槽 tab 即 `sentiment=negative`；行内徽标同 03。

### 05 · 事件脉搏
- 事件时间线（social/news/all 三 tab），事件卡：tag + 来源徽标 + 帖数 + 起止 + 摘要 + 正/负/中分布；点击 → `event` 锚点对话。
- **观点标签 TOP10**（用户真实看法横条）。（事件标签分布 TOP15 已删——与时间线信息重复，2026-09-22 双模式重构拍板。）

### 06 · 内容洞察
- **关键词云**：原生 canvas 实现（HTML 版，`echarts-wordcloud` 弃用）；词频来自 relevant 帖标题+正文（jieba + 停用词）。
- **舆情简报**：点击生成（LLM），保持点击式不做自动推送。

### 传播点报（viewMode=points，2026-09-22 新增）⚠️ 已于 2026-09-25 删除
> **本节已作废**——三分法重设计中传播点报整体删除（见下方「2026-09-25 三分法重设计」）。保留原文仅供历史追溯，勿据此实现。

传播团队的日扫行动点 feed。数据源 `GET /api/dashboard/points/{vid}`（默认排 archived；后端 last_seen desc 新鲜度默认序，**前端 PointsUI._sortByHeat 按 volume + 证据互动（▲×1+💬×5+→×10）重排**——两端口径契约见端点 docstring）。
- **页头摘要**：`在榜 N 个点：X 宣传 · Y 防守 ｜ 🆕/🔥/❄️ 状态分布`
- **筛选 chips**：全部 / 🟢宣传 / 🔴防守（pointsFilterOptions 带计数，active 双色）
- **点卡片**：类型/状态徽标 + origin 中文 + 在榜天数 → 一句话主张 → 指标行（volume/负面率/正向分/事件负面，全部判空渲染）→ 证据链（rep_comments：**author 空=LLM 转述标「（模型转述）」，有 author 显示 ▲赞**；证据帖前 3 可点开 post-detail Modal——evidence 10 字段直喂，无按 id 回捞端点）→ 建议动作行 → 问 AI（`openDialog("point",{point_id})`，上下文=点详情+证据帖互动排序前 5+代表评论，T8）
- 逻辑独立在 `static/js/points.js`（PointsUI 全局对象，dialog.js 同模式，先于 app.js 加载）
- 点生命周期：new→active(声量≥昨日×1.2)→cooling(连续 2 日<×0.8)→archived(3 日未匹配)，纯规则状态机在 `pipeline/analysis/point_miner.py`

## 5. 口径体系（前端视角）

三条服务端口径常量，前端通过副标题/文案呈现：

| 口径 | 含义 | 前端呈现位置 |
|---|---|---|
| `RELEVANT_ONLY` | 排除 `analysis_status='irrelevant'`（无关帖不进任何声量/榜/词云） | 全站默认，无需标注（不该出现的地方就不该有它） |
| `AUTHENTIC_AUTHOR` | 排除官方/经销商作者帖 | 情感环/趋势/维度副标题「已排除官方/经销商」+ 热帖/吐槽榜「官/商」徽标 |
| `SELF_ONLY` | 只算主车型帖（竞品帖不算） | 方法论区声明 |

时间窗：预设按钮改 `rangeStart/rangeEnd` → `onVehicleChange()` 全量重载；**例外**：top-posts 与 word-cloud 刻意不带时间窗（微博/抖音帖 `published_at` NULL 会被窗过滤静默丢帖——代码有注释，勿"修复"）。

## 6. 交互体系

**锚点对话（Dialog）**是全站下钻的统一出口：图表点击 → `openDialog(anchorType, anchorData)` → 右侧滑出面板，服务端 `_build_context` 按锚点类型聚合上下文喂 LLM。锚点类型：

| 类型 | 触发点 | 上下文内容 |
|---|---|---|
| `trend` | 搜索热度/讨论/情感趋势图点击日期 | 当日情感计数 + TOP3 帖 |
| `platform` | （预留）平台维度 | 平台帖数 + TOP3 帖 |
| `event` | 事件卡/观点标签/事件标签点击 | EventGroup 详情 + 相关帖 |
| `sentiment` | 情感环扇区/负面维度行点击 | 计数+占比、维度 Top5、该情感 TOP3 帖 |

其余交互：热帖/吐槽 tab 切换（服务端过滤）、帖子卡片 → 详情 Modal（维度情感条 + 评论摘要/genuine_sentiment）、时间预设保持滚动位置、车型联想 300ms 防抖。

## 7. 视觉规范

- **情感三色**：正面 `CHART_COLORS.pos` / 负面 `neg`（红）/ 中性 `neu`；负面语义色一律 `--neg` 系，涨跌语义（声量箭头）负面涨=红、降=绿。
- **风险档位**：low `#2e8b57` / medium `#d29922` / high `var(--neg)` + 红底渐变 / insufficient `#b9bcc4`。
- **卡片**：`.card` 统一白底圆角；`.card-title` + `.card-sub`（口径副标题，muted 小字）。
- **徽标**：平台徽标 `.hot-post-platform`（四平台+news 各自配色）、情感徽标 `.sentiment-badge`、官/商 `.hot-post-subject`、主题 chips `.tag-chip.tag-theme`。
- **榜单行**：`.hot-post-item` 圆形排名（前 3 accent 高亮）+ 标题单行截断 + meta 行。
- **响应式**：≤960px 双栏塌单列（radar-grid / trend-dual / bottom-dual 均已处理）。

## 8. 数据流约定

```
selectVehicle(v) → onVehicleChange()
  → Promise.all(14 loaders)   // overview/trend/sentiment-trend/dim/opinions/
                               // events/platform/top-posts/negative-radar/
                               // collection/progress/wordcloud/posts/controversial
                               //（event-tags 已删；points 由 PointsUI.load 单独拉）
  → renderAllCharts() ($nextTick 内逐图渲染)
  → 若 viewMode==='points'：PointsUI.load(this)（pointsLoading try/finally）

switchView(mode)：
  切 points → PointsUI.load
  切回 monitor → dispose 全部 11 个 echarts 实例 → 按 currentGroupId 分支重渲染
               （renderAllCharts 或 group 三图；分组分支需 $nextTick 等 v-if 重挂载）
```

- 每图一个 `renderXxxChart()`：`el` 不存在直接 return（面板未开）；实例缓存在 `this` 上防重复 init；`setOption(..., true)` 全量替换。
- `bindChartClick(chart, type)` 内置 `__clickBound` 防重复绑定（否则一次点击弹 N 个 Dialog——踩过）。
- `window.resize` 统一 resize 所有实例。

**新增出数端点的前端三件事**：loader 加进 `onVehicleChange` 的 `Promise.all`、state 加默认值、渲染函数挂进 `renderAllCharts`；并在 `tests/test_caliber.py` 补一行口径横扫（后端侧）。

## 9. 演进与已知取舍

**演进**：v3（严格骨架，redesign-preview 1:1）→ v6（四层递进+报告+锚点对话）→ v7/07-03 修复批 → 2026-09-16 负面雷达（03 区插入，原 03-05 顺延）。`redesign-preview.html` 是骨架设计稿，`demo.html` 是历史演示，均保留作参照。

**已知取舍**（有意为之，非缺陷）：
1. 单文件 app.js（~1300 行）不拆——零构建原则下拆模块要引打包器，得不偿失；以 `// --- 区块注释 ---` 分区导航。
2. 词云用 canvas 自绘而非 ECharts 插件——兼容性原因（§2）。
3. 报告保持点击生成——与后端口径同源，不做定时推送。
4. top-posts/word-cloud 无时间窗——NULL published_at 丢帖问题（§5）。
5. 采集频率为日级，故全站无"实时"语义，异常动效（告警条/实时大屏类）明确不做。
6. **点报无时间窗**——点的生命周期（new/active/cooling/archived）即时间语义，时间预设对点报不生效。
7. **列表区 cap**（反转卡 5 / 点卡证据前 3）——超视口长列表会触发全局 resize mid-render 崩 echarts（2026-09-21 实雷，二值实验 cap5 不崩/cap6 崩）。

## 健康分跨视图一致性（T4.4，2026-10-06 audit Phase 4）

车队总览与单车页健康分有意的差异（非 bug，产品需求）：

| 维度 | 单车页 `/overview` | 车队 `/fleet-overview` | 是否有意 |
|---|---|---|---|
| 公式 | `compute_health_score` 单一真相源 | 同 | ✅ 同源 |
| 口径 | SELF_ONLY+AUTHENTIC_AUTHOR+RELEVANT_ONLY | 同 | ✅ 同 |
| 时间窗 | 跟随用户窗（7/30/90 天） | 固定 30 天 | ✅ 有意（车队要可比基准） |
| 上界 | `< end+1天` | `< today+1天`（T4.2 补齐） | ✅ 已统一 |
| 无数据语义 | `None`（T4.1 统一） | `None` | ✅ 已统一 |
| 样本门槛 | `<20 insufficient` | `<20 insufficient` | ✅ 已统一 |
| 风险算法 | `/negative-radar` 多因子 | 简化单因子（负面率） | ✅ 有意（车队求快扫） |

**结论**：时间窗 + 风险算法是有意差异（车队视图定位"一屏扫完"，不求全量风险画像）；其余 3 处（无数据语义/上界/门槛）已在 audit Phase 4 统一。
