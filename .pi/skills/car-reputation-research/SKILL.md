# 车型社媒口碑调研（Prism 版）

## 铁律：真实可溯源（8 条）

1. 每条引用反馈必须附**来源平台 + URL + 抓取时间**（TikHub 结果的 `_meta.as_of`）
2. TikHub 数据是**外部 API 即时快照，不可复算**——结论中必须声明这一点（区别于库数据的 supported_by 行 ID）
3. 无法验证的内容（需登录的评论、凭记忆的细节）标"未核验"，不猜测不补全
4. 区分信源：真实车主 > 意向用户 > 媒体/自媒体 > 疑似水军；结论以真实车主一手反馈为准
5. 价格/销量/续航等多源交叉核验，注明口径（指导价/置换价/落地价）；库内有数据的（销量/口碑/配置）优先用 query_* 工具（红线#9 库优先）
6. 用户口述的旧信息（日期、购车细节）一律以平台页面实锤为准——已发生过口述日期误记
7. **画像输出边界**：画像输出限于"人群理解"颗粒度（如"40岁女性外贸从业者"），不输出可定位到具体个人的信息组合（住址小区级/手机号/证件类）；溯源清单 URL 属证据链，对管理者可见
8. **成本纪律**：TikHub 是付费 API，每轮调用配额由系统护栏统一限制（超限会被拦截，护栏值以系统为准）；达到上限即基于已有数据分析，数据缺口走假设清单范式（声明缺失+假设+缺什么能坐实），不硬凑

## 流程（两阶段协议——对标人工"先广扫、后深挖"的真实工作方式）

### 阶段一 · 扫描轮（用户首次提出调研/画像请求时）

1. **基本盘**：上市日期、价格体系、版本配置、订单/销量——**库优先**：query_sales/query_config/dashboards 工具（可复算）；库里没有再 web 搜索补（标注 URL 不可复算）
2. **平台扫描**：用 `social_search` 按平台搜主帖（抖音/小红书/微博/快手/哔哩），帖子归类（试驾/购买决策/价格争议/吐槽）。**配额纪律：扫描阶段省着用全轮配额（额度见铁律 8）**——扫描的目的是定位人选，不是把每个平台扫穿；用户续问再补。汽车之家论坛走 web 抓取（游客全通，URL 格式 `club.autohome.com.cn/bbs/thread/{hash}/{topicid}-1.html`）
3. **真实车主识别 + 候选人名单（阶段一的终点）**：特征=提车作业（提车日期/落地价/上牌细节）、持续用车更新、评论区答疑、**生活帖与汽车帖混合**（推断原料）；质量问题按"多人复现 > 单人单次"聚类。每个候选人给**信息密度评分**（账号资历/自述细节量/有无论证帖/内容构成），推荐 2-3 个"值得深挖的"并说明理由。
   **阶段一到此必须停**：把候选人名单交给用户点名——**不得自行进入深挖**。例外：用户在一句请求里已指名道姓（如"深挖 zkz8118"）→ 直接进阶段二，load_skill 时传 `named_target`（执行层状态门据此解锁深挖工具）。若用户只要"全网反馈汇总"（模板 A，无画像意图）→ 不需要点名，按模板 A 交付。
   **系统强制**：本阶段 `social_user_profile`/`social_user_posts`/模板 B 导出会被执行层**直接拦截**（返回拦截原因）——被拦不是故障，是状态门在执行两阶段协议；按拦截指引先出候选人名单即可，用户点名后自动解锁。

### 阶段二 · 深挖轮（用户点名后；开始时先 load_skill 重载本技能，防长会话纪律洗出）

4. **典型用户深挖**——**配额全部投被点名的 1-2 人，不做广撒网**。
   - **每人固定动作序列**：`social_user_profile`（主页：资料/IP/粉丝量）→ `social_user_posts` **逐页全翻，不只看汽车帖**（职业/家庭/性格/消费力从生活帖推断）→ 相关帖 `social_post_comments`（一手引语原话，评论区常自述落地价/提车细节）→ **汽车之家论坛长帖 web 逐帖精读**（被点名者是论坛 KOC 时的标准动作：fetch_content 读全文+评论区——这是逼近标杆深度的唯一素材通道）。**论坛 KOC 主页定位路线**：从其任一帖子页的作者链接进主页 → 先取资历统计（主帖数/回复数/热门帖/勋章）再逐帖读——主页统计是画像的硬骨架，缺了必补。**user_id 四种形态都可用：搜索结果 author 字段的昵称即可直接当 user_id**（实证："开奇瑞的杨仔😛"这类昵称可直接查通主页）——禁止以"搜索接口不返回原生 ID"为由跳过深挖
   - **选样密度标准**（用户让自行挑人时）：弃低密度号（纯转发/无自述/内容与车无关），优先"提车作业 + 持续用车更新 + 生活帖混合"的号——生活帖是推断职业/家庭/性格的原料
   - **推断授权（防宽泛的关键）**：画像必须包含**推断级细节**，三类推断明文授权——①身份推断（年龄/职业/家庭，从生活内容与自述推，如"晒装柜发货→外贸从业者"）②决策心理推断（对比淘汰原因/价格敏感度/情绪转折，从发帖时间线推）③行为模式推断（发帖习惯/话术风格/社区角色）。**每条推断必须挂依据**（哪条帖/哪句话），标注 [推断]；实锤标 [实锤·出处]；推不出的标 [未核验]——禁止无依据填充，也禁止只罗列实锤原文
   - **画像维度卡**（每人必填，模板见 deliverable-spec 模板 B）：用户速览（账号/注册/资历/粉丝）→ 人物（性别年龄/地域 IP/职业/家庭）→ 车辆（履历/现车配置/成交关键：价格定金补贴话术）→ 决策（对比池与淘汰原因/时间线/关键转折）→ 行为与内容（构成/习惯/风格）→ 用车实证（问题/好评/未满足需求）
   - **导出前自查**：硬门——被点名用户全部深挖完成、每人 6 维卡齐、溯源清单覆盖所有引用；软门——每人 ≥3 条 [推断] 级细节，不达标回 posts/论坛继续翻，不得导出。**本流程优先于三维度 SOP 的顺序推进**（社媒深挖是独立工作流）；**同会话同主题的后续追问延续本工作流，不得退化为库内 search_reviews 凑交付**
5. **交付**：调 `export_document` 出原生 .xlsx（表结构见 `references/deliverable-spec.md`，用 load_skill 加载），每个数字/引语可回溯到溯源清单。**典型用户画像/个案类交付必须用模板 B**（说明与来源/用户对照总览/每用户一个详解表/溯源清单）；阶段一被要求"全网汇总"则用模板 A。标杆样例=《风云T7典型用户分析》（说明与来源/用户对照总览/zkz8118-个案详解/作者A-个案详解/溯源清单-两人）

## 平台速查（Prism 实测 2026-10）

| 平台 | 工具 | 说明 |
|------|------|------|
| 抖音/小红书/微博/快手/哔哩 | social_search / social_post_comments | TikHub 免登录；画像/作品仅抖音+小红书（social_user_profile / social_user_posts） |
| 汽车之家论坛 | web 抓取（游客全通） | URL 格式 `{hash}/{topicid}-1.html`；老账号KOC长决策帖值得单独立案 |
| B站 | social_search(bilibili) 或 web 兜底 | 注意同系列标题（"终于轮到我"）混入其他车型，按车型名过滤 |
| 懂车帝 | 不做 | 搜索强制登录且内容与汽车之家高度重叠 |

## 陷阱

- 媒体互相转载=循环印证，必须追一手来源
- 上市初期真车主极少（实测：上市1周论坛72车友仅1位真车主），多数"反馈"是意向讨论或水军，勿高估样本
- 视频/帖子日期以页面显示为准（精确到分），防口述误记
- 同一数字不同口径（指导价 vs 置换价 vs 落地价）分开列，不混写
- **画像宽泛病**：只罗列"账号/车型/价格"级实锤 = 宽泛。深度来自"实锤 + 推断 + 依据"三层——标杆里的金句（"推算约53岁提前退休""曾梦想奔驰买不起"）全是推断级，每条都挂得出现依据
- 引语一律原话摘录，不转述不改写（保留口语和错别字）
- TikHub 是付费 API：搜索词先精准后泛化，避免一轮内反复试词烧配额
