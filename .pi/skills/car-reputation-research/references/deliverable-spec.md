# 口碑调研 Excel 交付规范（export_document 对接版）

用 `export_document` 工具生成原生 .xlsx。工具参数结构：

```
export_document({
  title: "xx车型典型用户分析",
  filename: "风云T7典型用户分析.xlsx",   // 可选
  sheets: [ { name, headers: [...], rows: [[...], ...] } ]
})
```

两个模板按任务选：全网扫描 → 模板A；典型用户深挖 → 模板B（可并存）。单 sheet rows 建议 ≤200（过大先聚合再导出）。

## 模板A：全网反馈汇总

| # | 工作表 | headers |
|---|--------|---------|
| 1 | 说明与来源 | 项目/内容 |
| 2 | 基本盘 | 项目/数值/口径/来源 |
| 3 | 好评维度 | 维度/帖数/代表性引语（原话）/来源链接/抓取时间 |
| 4 | 差评维度 | 同上 |
| 5 | 质量问题 | 问题/复现人数/车主帖来源链接 |
| 6 | 热帖清单 | 标题/平台/互动数/链接 |
| 7 | 溯源清单 | 平台/标题/时间/URL/抓取时间 |

## 模板B：典型用户分析

| # | 工作表 | headers |
|---|--------|---------|
| 1 | 说明与来源 | 项目/内容（含选样逻辑、人群覆盖、口径声明） |
| 2 | 用户对照总览 | 维度/用户1/用户2/…/来源备注 |
| 3+ | 每用户一个详解表 | 项目/内容（画像/决策链/购车时间线/引语原话+提问者背景+URL） |
| N | 溯源清单 | 用户/类别/标题/时间/链接（两人所有主页/主帖/视频/评论 URL 全列） |

## 模板B：典型用户分析

**格式总纲（三定律，违反即返工）**：
1. **维度行序 = 人物叙事弧**：先讲这是谁（身份），再讲他的车（履历），再讲他怎么买（决策）——禁止按"账号数据→遥测数据→观点"的运营看板式罗列
2. **个案详解 = 区块化章节**，不是平铺键值表：区块用「— XXX —」分隔行，决策时间线按日期排序、一行一个节点
3. **内容写法 = 叙事句**：每格写完整的话，推断过程和引语原话混排进句子（见下方坏例/好例），禁止电报式短语

**对照总览：维度行序钉死（照抄，勿自创顺序）**：

| 行序 | 维度行 | 内容要求 |
|---|---|---|
| 1 | 性别 / 年龄 | 实锤或 [推断·依据]（"推算约 53 岁（2008 年 35 岁购首车）"式） |
| 2 | 地域 / IP | 常驻地 + IP 属地分开写 |
| 3 | 职业 / 家庭 | [推断·依据] 从生活帖/自述推 |
| 4 | 账号性质 | 平台/注册年限/资历细目（主帖数/回复数/热门/勋章）/粉丝量 |
| 5 | 车辆履历 | 历史车 → 现车（代际序列） |
| 6 | 对比车型 / 淘汰 | 对比池逐个 + 淘汰原因（等车时长/配置缺陷/价格） |
| 7 | 成交关键 | 价格/定金/置换补贴/跨地域/对外话术 |
| 8 | 用车实证 / 主要抱怨 | 已发生的真实问题 + 情绪 |
| 9 | 情绪 / 社区角色 | 正负倾向 + 在社区里的角色（KOC/素人/答疑者） |

末列固定为"来源/备注"。维度信息不全时写"未披露"，不删除该行。

**每用户个案详解表：区块结构（3 列：区块 | 项目 | 内容）**：

| 区块 | 行 | 内容规范 |
|---|---|---|
| — 用户速览 — | 账号 / 社区资历 / 个人情况 / 行为特征 | 资历写到细目（"262 主帖/5715 回复/12 篇热门帖，持××达人勋章"级）；行为特征=推断级 |
| — 车辆与成交 — | 车辆履历 / 现车配置 / 成交关键 | 履历按代际（"长安逸动→CS75→众泰→风云T7"）；成交含价格/定金/补贴/对外话术 |
| — 决策时间线 — | 按日期排序，一行一个节点 | 每行=日期 + 事件 + 引语/来源（"2026-07-25 发帖问海狮05EV：等车 45 天+保险 6500 → 淘汰"） |
| — 画像推断 — | 身份推断 / 决策心理 / 行为模式 | 每行 [推断·依据] 三段式：观察→推断→依据 |
| — 用车实证 — | 问题 / 好评 / 未满足需求 | 引语原话「」内嵌 |

**写法对照（坏例 vs 好例）**：

- ❌ 坏例（电报式）：`提车13天累计3500km`
- ✅ 好例（叙事+推断）：`提车 13 天跑 3,500 km（日均约 269 km）——被网友质疑"262km/天谁信"，本人未回应 [实锤·评论区]；高强度里程特征与其"顺风车师傅"昵称语境互证 [推断·帖文]`
- ❌ 坏例（无过程）：`约 53 岁`
- ✅ 好例（推断三段式）：`自称"退休老头"——2008 年 35 岁购首车，推算约 53 岁提前退休 [推断·自述+时间推算]`

**标杆样例**：《风云T7典型用户分析》（2026-09-02）：说明与来源 / 用户对照总览（上表 9 行序）/ zkz8118-个案详解（区块化）/ 作者A-个案详解 / 溯源清单-两人。

**画像维度卡（每用户详解表必含的 6 维字段，防宽泛）**：
| 维度 | 字段 | 证据要求 |
|---|---|---|
| 用户速览 | 账号（平台/注册/昵称/ID）、社区资历（发帖/回复/热门/勋章/粉丝）、IP 属地 | [实锤·出处] |
| 人物 | 性别年龄、地域、职业、家庭 | 实锤或 [推断·依据]（从生活帖推断职业家庭） |
| 车辆与成交 | 车辆履历（历史车→现车）、现车配置、成交关键（价格/定金/补贴/对外话术） | [实锤·出处] 逐条 |
| 决策 | 对比池与淘汰原因、决策时间线（看车→对比→下定→提车）、关键转折 | 实锤 + [推断·依据] |
| 行为与内容 | 内容构成（汽车帖 vs 生活帖）、发帖习惯、话术风格 | [推断·依据] |
| 用车实证 | 真实问题（多人复现>单人）、好评点、未满足需求 | [实锤·出处] 引语原话 |

每字段标注证据等级：[实锤·出处] / [推断·依据] / 未核验（删除或标注）。只有实锤罗列、没有推断级细节的画像 = 宽泛，不达标。

**导出前自查清单（缺一不得导出）**：
1. ≥2 个真实用户完成深挖（每人 social_user_profile + social_user_posts 均已调用）
2. 每用户详解表含：用户速览 + 决策时间线 + 引语原话（非转述）
3. 溯源清单覆盖正文引用的每一条证据（URL 全列）
4. 未核验信息已标注或删除
5. 说明与来源含 TikHub 不可复算声明 + 抓取时间

## 原则

- 引语一律原话摘录，不转述不改写（保留口语和错别字）
- 每个日期、价格标注来源（视频URL/帖子链接）
- 无实锤的信息标"未核验"或直接删除，不进交付物
- TikHub 来源的每条数据附抓取时间；库来源（query_*）附行 ID 与 as_of
- 说明与来源 sheet 必须声明："社媒数据来自 TikHub API 即时快照（不可复算），抓取时间见溯源清单；库数据可复算（supported_by 行 ID）"
- 导出成功后在回复正文中用 markdown 链接给出下载地址
