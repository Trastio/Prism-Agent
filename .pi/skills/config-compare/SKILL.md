# 配置对比（差异/差价两用）

## 纪律（先读）

1. **对象核验前置（红线#7）**：先 `resolve_series` 确认用户问的车系在库内并拿 series_id。库内无快照的车系如实报缺，不硬比。
2. **版型选择**：用户问的是车系级（没说版型）→ 先 `get_trims` 看版型列表，**默认各选最高配（顶配）做能力对标**（在售最高配；若最高配配置缺失，如实声明并按次高配降级）；只有用户明确问"主销/走量/性价比"时才改选主力版型。开口第一句声明所选版型（"以银河E5 635 智充激光版 vs 风云T7 600km 智享版为例"）；用户指定"顶配 vs 顶配"等照办。
3. **数字只来自工具**：判定和金额必须来自 `compare_configs_valued` 返回值；禁止心算或改写。**sel 必须是数组** `["mid:spec","mid:spec"]`（不要传逗号字符串）。
4. **口径声明（轻量）**：出现金额的结论说一句"按配置差价口径"即可；"未含看板手填覆盖"属于内部溯源细节，仅在用户追问数据来源时说明。
5. **结论不越界**：配置对比只回答配置维度；不下销量归因，不外推产品力优劣（那是三维度交叉验证的事）。
6. **C2 增量假设**：城市NOA 相对高速NOA 计增量价（领域假设：城市NOA 车型必有高速NOA；金额以差价清单为准）。涉及 C1/C2 的金额结论随句披露。
7. **正文人话（SYSTEM.md 输出受众分层）**：回复正文不出现工具名/表名/字段名/引用格式原文（get_trims、sales_trim、config_diff: 等）——提交 CLAIM 时的参数格式与对用户说的话是两回事；表格列名用业务语言（"指导价""CLTC 续航"），内部名只在用户追问来源时一句话带过。

## 流程

1. **核对象**：`resolve_series` → series_id；版型不确定走纪律 2。
2. **取判定**：`compare_configs_valued`，sel 数组、第 1 个=基准（用户语境的"本品"放第 1）。返回 rows（逐项判定）+ diff.columns（汇总）+ guide_prices（指导价）。
3. **输出分支（听用户问的是哪种）**：
   - **纯差异问法**（"配置差在哪/有什么区别/哪个配置高"，没提钱）：五态清单分组呈现——**多**（列项）、**少**（列项）、**同**（汇总一句）、不计/缺采（留痕）；**不出现金额**，最多结尾一句"若按差价口径折算，配置差约 ±X 元，需要的话我可以展开"。
   - **差价问法**（"值不值差价/贵在哪/多值多少钱"）：在差异清单上加金额：大额差异项点名（如"800V、热泵、真皮座椅"）+ 小额汇总 + 配置优势合计 + 拉平句式："贵 X 万，但配置多值 Y 万，**拉平后还多 Z**"（正=值，负=不值）。
4. **缺口处理**：`missing_rules` 非空导致汇总被拒是**正确行为**（规则表缺价不脑补）——按数据缺口假设范式：声明缺哪些项定价 → 列假设（标证据强度）→ 附"缺什么能坐实"。禁止自行估价凑总数。
5. **降级路径**：指导价拿不到 → 只出差异/配置优势，不出拉平价并说明；compare_configs_valued 连续失败 → 回退 `get_config_detail` 出原始配置对照（无判定无金额），并声明口径降级。
6. **交付**：带金额的结论走 `submit_conclusion`，supported_by 用 `config_diff:{midA}/{specA}/{midB}/{specB}`（对应本次配对）；纯差异结论同样引用所对比版型的 `config_snapshots:{mid}/{spec}`。numbers 提交两条硬规则：**①value 填纯数值**（去单位去千分位——"12.8" 而非 "12.8英寸"，"65000" 而非 "6.5万"）；**②自己心算的差价/合计/比值一律 source="derived"** 并在 derived_from 列出参与计算的工具源数字，禁止把计算值标成 source="tool"。

## 边界

- 只覆盖库内有配置快照的车系（覆盖量随采集扩容变动，以库为准）；差价清单外的差异（如激光雷达）如实说明"清单外"，不硬套。
- 看板端手填价是内存态不落库，本工具读不到。
- 底价（终端成交价）非本工具口径；用户给底价可代算"综合竞争力=配置优势+竞品底价−自品底价"，须声明这是对话内计算、底价为用户口径。
